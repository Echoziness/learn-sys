## 2. 领域选型

### 2.1 决定

- **主演示库：大数据工程技术人员（初级 · 大数据分析方向）**
  国家职业技术技能标准（2021 年版），职业编码 2-02-10-11，人社部 + 工信部联合发布。
- **泛化性演示库：人工智能工程技术人员（初级 · 人工智能应用产品集成实现方向）**
  同体系标准（2021 年版），职业编码 2-02-10-09，做 30~50 条小切片，演示"换库即换领域"。
- **整体叙事定位：面向"数字技术工程师培育项目"的个性化培训引擎。**

### 2.2 依据

| 维度 | 大数据分析（选定） | 软考软件设计师（落选） | AI 应用集成（降为切片） | 1+X Web 前端（出局） |
|---|---|---|---|---|
| 条目式友好 | 方法体系边界清晰（SQL/统计/算法） | 考纲即条目，最优 | 概念+流程混合，工程文本松散 | — |
| 内容稳定性 | 经典内容数十年不变 | 2018 大纲 8 年未改版 | **致命伤**：2021 标准不含大模型，写经典显旧、写新的无背书 | — |
| 权威来源 | 标准 PDF 公开 + 官方教材（人事出版社）+ SQL/pandas 公开文档 | 备考资料海量但应试导向 | 教材无电子版，自编成本高 | — |
| 实操演示性 | SQL/Python 可当场运行，视频效果好 | 应试无实操 | 较好 | — |
| 应用型人才对口 | 专科起点，高职/应用型本科对口 | 资格认证导向 | 专科起点 | — |
| 叙事风险 | "人工智能等"场景覆盖 | 讲不出"产业实操" | 赛题点名 AI（保留为切片叙事） | **2025-12-31 X 证书整体移交人社部，体制撤销中** |

**结论逻辑**：主演示库必须同时满足条目式 + 内容稳定 + 权威背书 + 可实操，只有大数据分析四项全占；AI 方向保留为泛化切片以维系讯飞 AI 叙事共鸣。

### 2.3 知识库内容来源

1. 标准 PDF（政府官网公开）→ 条目骨架：职业功能 / 工作内容 / 相关知识要求直接映射为条目树；
2. 条目正文：SQL 官方文档、pandas 官方文档、经典统计学/数据挖掘公开教材的**理解性改写**（禁直接复制，版权合规）；
3. 生产 SOP：AI 生成草稿 → 执行者对照来源核对、补全字段 → 核心抽审 10%；
4. 每条标注 `source` 出处，溯源链直通官方文档。

## 3. 技术栈选型

### 3.1 定型总表

| 层 | 选型 | 关键理由 |
|---|---|---|
| 编排框架 | **LangGraph Python 1.x** | 见 3.2 |
| 后端 | **FastAPI + SSE** | SSE 单向推送图执行事件，HTTP 自动重连，比 WebSocket 实现量减半 |
| 存储 | **SQLite 全家桶**：业务表 + FTS5 全文 + sqlite-vec 向量 + RRF 融合 | 单文件 DB、docker 内零额外组件、评委环境零外部依赖 |
| Embedding | **BGE-M3 本地**（sentence-transformers） | 中英混合主流开源；检索栈全离线；评委只需 1 个 LLM key；批量评测零成本 |
| 前端 | **Next.js 15 + TS strict + Tailwind v4 + shadcn/ui + React Flow + Recharts** | 2026 年 AI 生成代码收敛栈，语料密度天花板 |
| 交付 | **docker compose 一键起**为主交付；Electron 为 P2 可选加分 | 比赛交付标准形态 |
| 语言约定 | Python 3.11+（core/api/evals）+ TypeScript strict（web） | 类型锚点：Pydantic schema → JSON Schema → 生成 TS 类型，SSOT 在 Python 侧 |

### 3.2 编排框架：LangGraph Python（否决 JS 版）

**证据**（2026-07 检索）：

- LangGraph 1.0 于 2025-10 GA（Python/JS 同步），Klarna/LinkedIn/Uber/Replit 生产在用，token 开销为三大框架最低（+9%）；
- **AutoGen 已死**：微软转入维护模式，由 Microsoft Agent Framework 1.0 接替；CrewAI 无持久化只适合原型；
- **JS 版 parity 差距是实坑**：GitHub issue #1767——`createAgent` 在 JS 版无法作为 StateGraph 节点，官方 1.0 核心组合模式在 JS 侧不成立；第三方生产团队评价"Python-vs-TypeScript gap is real"；月下载 LG.py 4.3M vs LG.js 1.8M。

**结论逻辑**：本项目创新核心是自定义图逻辑（辩论回路、子图、条件路由），重度使用 parity 差距所在的高级特性，6 周无预算踩框架坑。

### 3.3 否决记录（防止重提）

| 方案 | 否决原因 |
|---|---|
| AutoGen | 2026 年已处维护模式，无新功能 |
| CrewAI | 无持久化层，工作流中途失败须从头重跑；生产案例全部匿名不可验证 |
| Chroma | 引入第二个存储组件；SQLite 全家桶可单文件承担全部检索，部署更简 |
| LangGraph JS | 见 3.2 |
| Streamlit / Gradio | 调度可视化+学情报告+资源排版三画面需求超出其布局能力；Next.js 为 AI 语料收敛栈 |
| Chainlit | 2025-05 创始团队退出转社区维护，2025 底曝两个高危漏洞 |
| Electron（作为 MVP 交付） | PyInstaller 捆绑 Python 后端成本 2~3 天，挤占关键路径；降为缓冲周可选 |
| Tauri | Rust 语料密度低，且后端为 Python 无法享受其红利 |
| 微服务 / 消息队列 | 单人项目最大隐性风险：AI 默认倾向过度架构，AGENTS.md 明令禁止 |

### 3.4 模型策略

- 统一走 **OpenAI 兼容协议**，provider 抽象层切 base_url + api_key + model 即换模型；通过环境变量注入，不预设模型名或 provider；内部实现为 `AsyncOpenAI` client，不做二次封装厂商 SDK。

## 4. 架构设计

### 4.1 仓库结构（模块化单体）

```
learn-sys/
├── core/            # Python 包：编排核心（禁止模块级副作用）
│   ├── agents/      # 每 agent 一文件；节点签名 (state, *, provider, model)
│   ├── state.py     # AgentState + agent 间消息 Pydantic 模型（SSOT）
│   ├── graph.py     # build_graph(settings, provider, retriever) 依赖注入装配
│   ├── llm.py       # LLMProvider + chat_validated 校验重试
│   ├── retrieval.py # Retriever：FTS5(CJK逐字切分) + sqlite-vec + RRF + 覆盖度判定
│   ├── embedding.py # BGEEncoder（仅组合根 import）
│   ├── config.py    # Settings：唯一 env 读取点
│   └── logging.py   # structlog JSON
├── api/             # FastAPI 薄层：REST + SSE 推送图执行事件（Phase 3 挂载）
├── scripts/         # 组合根：init_db.py（幂等 loader）+ run_cli.py
├── data/
│   ├── seeds/<domain>/entries.jsonl  # 知识条目（一等数据文件，换目录即换领域）
│   ├── seeds/profiles/*.json         # 画像种子
│   └── knowledge.db                  # 业务+FTS5+vec 单文件
├── tests/           # pytest（与 evals/metrics.py 同口径）
├── evals/           # metrics.py（指标 SSOT）+ profiles/ + run.py
├── web/             # Next.js 15：调度可视化 / 学情报告 / 资源展示（Phase 4）
└── docker-compose.yml
```

**组合根纪律**：依赖（Settings / LLMProvider / Retriever / 编译图）在组合根（scripts/、api/）构造一次并显式注入；core/ 任何模块 import 时不产生副作用（不建 client、不加载模型、不读 env）。该结构使 pytest 可 import 全部被测代码（<1s），是"新功能写完即写 pytest"的物理前提。

### 4.2 多智能体编排流（8 节点 + 辩论回路）

```
diagnose(学情诊断: 画像+测试 → 盲区锚定条目ID)
  → plan(路径规划: 盲区按前置依赖拓扑排序, 纯算法无LLM)
  → retrieve(FTS5+vec 混合检索, RRF 融合, 覆盖度判定)
  → generate(生成: 强制引用, 输出 schema 挂 evidence_ids)
  → review(审核: 规则校验 + NLI 蕴含判断) ─┬─ 通过 → deliver(讲义/实操指南/分阶题 ×3形态 + 溯源清单)
                                            ├─ 打回(结构化审核意见, ≤3 轮) → generate
                                            └─ 轮次耗尽 → 降级: 仅保留已通过论断重组+移除声明
  → assess(生成分阶测试题, 同走审核链)
  → feedback(答题结果 → EMA 更新掌握度 → 决策: 降维解释 / 进阶挑战 / 下一主题)
```

各节点职责、可读/可写 state key、隔离红线见 `需求规格说明书.md` §3（Agent 名册与上下文隔离总表），该表为唯一事实源。当前进度：diagnose/retrieve/generate/review 已上线，plan/deliver/assess/feedback 按 Phase 2-3 排期接入。

### 4.3 防幻觉三层机制（创新性 25 分的核心叙事）

1. **生产约束（结构层）**：生成 Agent 输出 schema 强制每条论断挂 `evidence_ids`；检索置信度过低的知识点标记"知识库未覆盖"并拒答——宁可说没有，不可编；
2. **信息隔离审核（机制层）**：生成 Agent 看得见画像、无自由发挥权；审核 Agent 看得见知识条目原文、**看不见画像**——从架构上瓦解"个性化 vs 专业性"的单模型矛盾（赛题原文点名的痛点）。审核任务从开放事实核查**降维为封闭 NLI 蕴含判断**（支持/部分支持/不支持），这是 LLM 最可靠的任务类型；
3. **辩论留痕（对抗层）**：打回时审核意见结构化（哪条论断、什么问题、建议动作），生成 Agent 逐条回应（采纳/反驳+理由），辩论链全程可追溯——既是防幻觉机制，又是演示视频里"多智能体博弈可视化"的核心素材。

### 4.4 上下文设计原则

- 每节点只拿职责内**最小上下文**；state 传结构化产物，**不传对话史**；
- 对话日志仅用于画像更新，永不进生成上下文（防污染）；
- 生成 Agent 输入：知识条目原文 + 画像摘要（掌握度向量 + 1~2 个问卷直采风格标签）+ 大纲 + 最近一轮审核意见；
- Agent 间消息全部 Pydantic 强类型 schema 约束。

### 4.5 关键数据 Schema

知识条目（SQLite，`scripts/init_db.py` 内 SCHEMA 为实现 SSOT）：

```sql
CREATE TABLE knowledge_entries (
  id TEXT PRIMARY KEY,        -- 如 BDA-SQL-001
  domain TEXT,                -- 领域标识（= seeds 目录名），换库即换领域
  title TEXT NOT NULL,
  content TEXT NOT NULL,      -- 条目正文（理解性改写）
  prerequisites TEXT,         -- JSON 数组：前置条目 id
  difficulty INTEGER,         -- 1-5
  keywords TEXT,              -- JSON 数组
  source TEXT                 -- 出处（溯源链终点）
);
-- FTS5 独立表 knowledge_fts(entry_id UNINDEXED, text)：
--   text 为 title+content+keywords 经 CJK 逐字切分后的文档
--   （unicode61 把连续中文当单个长 token，不切分则"统计"命中不了"描述性统计"；
--     trigram 对 2 字中文词会静默匹配全表，已实测排除）
-- sqlite-vec 表 knowledge_vec(embedding FLOAT[1024])：维度随 encoder 自适应
```

Agent 间消息（`core/state.py` 为实现 SSOT）：LearnerProfile / RetrievedEntry / DraftClaim（evidence_ids min_length=1，无证据论断 schema 层拒绝）/ ReviewNote（含 suggestion 打回建议）/ DiagnoseOutput / GenerateOutput / ReviewOutput；`review_history` 使用 append reducer——辩论链只增不改，全程可追溯。

学习者画像（JSON，`data/seeds/profiles/`）：

```json
{
  "learner_id": "L001",
  "background": { "education": "本科大二", "major": "机械", "goal": "转行数据分析" },
  "mastery": { "BDA-SQL-001": 0.9, "BDA-STAT-003": 0.3 },
  "style_tags": ["代码优先"]
}
```

画像纪律：掌握度向量是唯一硬数据（测试驱动，EMA α=0.3 更新）；风格标签仅 1~2 个问卷直采维度，禁止 AI 自由推断性格。

## 5. 评测体系（实用价值 30 分的命门，先行定义口径）

| 指标 | 目标 | 计算口径 | 方法 |
|---|---|---|---|
| 幻觉率 | <5% | 被判"无溯源支持"论断数 / 总论断数 | 审核链自动判定 + 执行者人工抽检 20% 做信度验证 |
| 画像-资源适配准确率 | ≥85% | 资源难度落在画像 ZPD 区间的比例 | 规则计算 + LLM-judge 双轨 |
| 知识点覆盖率 | ≥90% | 资源覆盖知识点 ID 数 / 诊断盲区集合 | 纯程序计算 |
| 测试用例 | ≥50 组 | 画像生成器批量造差异化画像 × 生成任务 | evals/ 脚本，批量评测时嵌入本地 LLM provider |

单元测试（pytest）与评测脚本同源：多智能体协同调度逻辑 + 领域知识生成准确性为核心测试对象（赛题提交要求）。

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| AI 生成代码过度架构 | 高 | AGENTS.md 明令模块化单体、禁微服务/MQ；新依赖须先记录理由 |

| LangGraph 高级特性坑（子图/流式） | 中 | W1 先做技术验证而非业务代码；只用官方文档确认过的 API |
| 知识库进度拖期 | 高 | W1 即启动并外包执行者；种子条目 30 条先支撑链路开发，不等待全量 |
| 评委环境无法跑 LLM API | 中 | docker compose 内置 1 份预生成的完整运行记录（含中间数据），支持"回放模式"演示 |
