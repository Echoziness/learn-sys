## 1. 作品概述

### 1.1 问题与思路

赛题指出了大模型在垂直领域教育资源生成中的核心矛盾：**"个性化适配"与"专业质量把控"在单一模型架构下难以调和**——放开限制去迎合学情，专业内容失去准确性；严格限制以确保准确性，生成的资源又失去个性化意义。

赛题给出的解题方向是"多智能体协同决策"：由学情诊断 Agent 锚定盲区、领域专家 Agent 依托知识库生成内容、审核裁判 Agent 交叉验证，通过多角色的博弈与协同，同时拿到"个性化"与"高保真"。

本作品完整实现了这一思路，并进一步回答了赛题价值主张中最关键的一问：**生成的资源能否沉淀复用**。系统的定位不是"一对一 AI 陪聊"，而是——

> **面向职业培训的个性化学习资源生产引擎**：导学会话是资源的生产过程，每一轮教学中通过审核的内容实时沉淀为可溯源、分难度的学习资源包；同一知识库 + 不同学习者画像 → 不同的资源包；产出的资源与知识库同构，可直接回流入库再次使用。

### 1.2 四类证据物（全部可验证）

| 证据物 | 内容 | 位置 |
|---|---|---|
| ① 可视化系统 | 学生面导学工作台、裁判面多智能体协同调度可视化（React Flow）、学情报告三图（Recharts） | `web/`（可运行、可回放） |
| ② 指标数字 | 50 组画像全量评测：**幻觉率 0.44%（<5%）/ 画像-资源适配率 99.0%（≥85%）/ 知识点覆盖率 97.2%（≥90%）**；审核消融对照：无审核回路裸幻觉率 8.86% → 有回路 0.44% | `evals/results/` |
| ③ 测试数据 | 大数据工程技术人员（初级）领域知识库切片 31 条 + 50 组差异化画像 + 完整输入输出示例（画像→协同决策中间数据→最终资源） | 交付包 `03-测试数据包/` |
| ④ 可部署源码 | 开源仓库 + 本地部署说明 + 交付包生成脚本，已在干净环境（Windows）实测复现 | 源码仓库 / `docs/部署说明.md` |

### 1.3 一句话总览

学习者输入画像 → 系统一次性诊断出知识盲区并切出学习路径 → 逐主题进行"生成-审核"博弈式教学、"出题-判分-决策"检验式交互 → 每个教学轮次的合格内容实时沉淀为三形态资源包（讲义 / 分阶题 / 实操指南）→ 会话结束产出学情报告，资源可条目化导出回流知识库。**全流程每一环都可在裁判面可视化审计、可回放复现。**

## 2. 总体方案设计

### 2.1 产品定位与用户旅程

系统服务两类角色：

| 端 | 角色 | 得到什么 |
|---|---|---|
| 学习者 | 培训学员 | 一对一导学会话：讲解有出处、听不懂会换方式、做错了回头补 |
| 培训管理者 | 院校 / 企业培训部门 | 每位学习者的资源包 + 学情报告；多智能体调度的全程可视化与审计 |

**主演示场景**：大数据工程技术人员（初级·大数据分析方向）职业培训——取材自国家职业技术技能标准（2021 年版，职业编码 2-02-10-11），条目式友好、内容稳定、权威背书、SQL/Python 可实操演示。架构上领域与代码完全解耦：**换 `data/seeds/` 目录即换领域**（泛化能力论证见 §8.5）。

典型用户旅程（演示主线）：

```
学习者输入画像（教育背景 / 经验 / 目标 / 初始掌握度）
  │
  ▼
诊断 Agent（LLM 一次，可复现）：锚定知识盲区条目 + 难度层级
  │
  ▼
课程切片（确定性纯函数）：盲区投影 → 前置链闭包 → 难度过滤 → 拓扑排序
  │
  ▼
┌─ 逐主题导学会话（资源的生产过程）──────────────────────┐
│ 教学生成（每条论断强制挂证据链）→ 审核裁判（NLI 逐条裁决， │
│ 打回重写可见）→ 检验（选择题→回答题阶梯，错答有脚手架）    │
│ → 判分（规则预筛 + LLM 复核）→ 决策（前进 / 重教 / 降维）  │
│        每轮合格产出实时沉淀为资源包                        │
└──────────────────────────────────────────────────────────┘
  │
  ▼
交付：三形态资源包（带溯源链）+ 学情报告（盲区雷达 / 难度匹配 / 路径图）
  │
  ▼
资源条目化导出 → 与知识库同构 → 回流入库（产出物可复用的硬证明）
```

### 2.2 总体架构：四层模块化单体

运行态组件恒定且极简：**一个 Python 进程（后端）+ 一个 Node 进程（前端）+ 一个 SQLite 文件**。不引入任何额外服务组件，评委环境零外部依赖。

```
┌─────────────────────────────────────────────────────────────┐
│ 决策可视化层   裁判面（React Flow）+ 学生面 + 报告页 + 资源库 │ ← 体验分载体
├─────────────────────────────────────────────────────────────┤
│ 会话服务层     FastAPI 薄层 + 会话编排服务 + 统一事件流        │ ← 事件生产/消费
├─────────────────────────────────────────────────────────────┤
│ 教学内核层     LLM 智能体节点 + 确定性纯函数                  │ ← 创新分载体
│               （出题/判分/掌握度/切片/资源组装）              │
├─────────────────────────────────────────────────────────────┤
│ 数据层         SQLite 单文件（知识库 + 会话 + 资源包 + 事件流）│
└─────────────────────────────────────────────────────────────┘
```

**依赖方向单向**：`前端 ─(SSE/REST)→ 后端 API → 教学内核 → 数据`。后端 API 是薄层（只做序列化、转发、推流），全部业务逻辑在教学内核；内核不接触网络层。

### 2.3 核心设计原则

| 原则 | 说明 | 落地位置 |
|---|---|---|
| **策略与措辞分离** | 教学决策（教什么、出什么题、进/停/退）全部由确定性纯函数裁决；LLM 只负责把策略翻译成学生能理解的语言 | `core/mastery.py`、`core/assess.py`、`core/plan.py` |
| **掌握度驱动** | mastery（0-1 数值）是系统中枢——题型选择、前进/重教/降维、巩固模式、进阶挑战全部由它驱动 | `core/mastery.py`（唯一事实源） |
| **可审计** | 每步决策可溯源：哪个 agent、基于什么证据、输出什么裁决；统一事件流全程记录 | `session_events` 一表三用 |
| **fail-closed** | 无证据即判错、无裁决视为不支持、无判分要点即回退从严——所有兜底路径宁严勿松 | 全链路（§4.5 / §4.6） |

### 2.4 技术选型

| 层 | 选型 | 关键理由 |
|---|---|---|
| 多智能体编排 | **LangGraph (Python) ≥1.0** | 条件边 + 子图是"审核打回回路"的天然表达；生产级成熟度（Klarna/LinkedIn/Uber 在用）；否决 AutoGen（已入维护模式）、CrewAI（无持久化） |
| 后端 | **FastAPI + SSE** | SSE 单向推送图执行事件，比 WebSocket 实现量减半；异步原生 |
| 存储与检索 | **SQLite 全家桶**：业务表 + FTS5 全文检索 + sqlite-vec 向量检索 + RRF 融合 | 单文件、零外部依赖；否决 Chroma 等（避免引入第二个存储组件） |
| Embedding | **BGE-M3 本地**（sentence-transformers） | 检索栈全离线，评委只需一个 LLM key；批量评测零成本 |
| LLM 接入 | OpenAI 兼容协议，`base_url + api_key` 注入 | 不预设厂商与模型名，一处配置切换 |
| 前端 | **Next.js 15 + TypeScript strict + Tailwind v4 + shadcn/ui + React Flow + Recharts** | 主流收敛栈；React Flow 承载协同调度图、Recharts 承载报告三图 |
| 交付 | **本地部署**（两进程 + 一个文件） | 赛题无容器要求；本地部署失败面最小（曾实现 Docker 方案，实测构建网络/代理/镜像体积多处踩坑后改判，决策过程留档） |
| 包管理 | Python → uv · JS → pnpm | 依赖锁定、可复现 |


**关键工程决策**：

- **图只编译一次**：教学子图在程序启动时装配编译，运行期只做调用；智能体节点签名统一为 `(state, *, provider, model)`，依赖显式注入，内核无全局状态；
- **事件发射不进智能体**：节点保持纯粹（只管输入输出），编排层消费图执行流并转换为会话事件——内核零改动即同时服务 CLI 与 Web 两个驱动端；
- **进度从历史推导**：会话无任何内存态，所有进度（是否已教、是否脚手架待答、重教上下文）由数据库历史推导——进程重启即续跑，后端天然无状态。

## 3. 多智能体协同体系设计

### 3.1 智能体全景（9 个职责单元）

赛题要求"至少 3 个职责分工明确的智能体，实现分析-生成-校验-决策协同闭环"。本系统实现 **9 个职责单元**，其中 6 个调用 LLM、3 组为确定性规则/纯函数，形成"LLM 负责语言与语义、纯函数负责策略与裁决"的分工：

| 智能体 | 职责 | 类型 | 在闭环中的角色 |
|---|---|---|---|
| **diagnose**（学情诊断） | 画像 → 知识盲区条目清单 + 难度层级 + 画像摘要 | LLM（temperature=0，可复现） | **分析** |
| **retrieve**（证据检索） | 锚定条目 + FTS5/向量混合检索 + 难度闸门过滤 | 确定性 | 分析（供料） |
| **generate**（领域知识生成） | 条目 + 画像摘要 → 教学论断（强制证据链 + 分层） | LLM（受证据约束） | **生成** |
| **review**（审核裁判） | 逐条论断 NLI 三分类裁决 + 打回意见 | LLM + 规则兜底 | **校验** |
| **question**（出题） | 回答题/概念辨析题/脚手架生成 + 追问判定与解答（服务端校验兜底） | LLM + 校验 | 校验（检验学生） |
| **feedback**（判分复核） | 作答的概念级复核 + 教学评估 + 题意核对检查单 | LLM + 规则兜底 | 校验 |
| **distill**（误区提炼） | 错题/脚手架原料 → 知识化误区表述（讲义锚定校验，资源回流用） | LLM + 校验 | 生成（资源侧） |
| **plan / assess / mastery**（切片/出题选择/掌握度） | 课程切片、题型选择、掌握度数学、进/停/退决策 | **纯函数** | **决策** |
| **deliver**（资源组装） | 三形态资源包装配归档 + 条目化导出 | 纯函数 | 交付 |

"分析-生成-校验-决策"闭环在系统中的具体形态：

```
诊断(分析) → 切片(决策) → 检索(分析) → 生成 ⇄ 审核(校验·博弈回路)
  → 出题(校验) → 学生作答 → 判分(校验) → 掌握度(决策) → 前进/重教/降维
  → 每轮合格产出 → 资源组装(交付)
```

### 3.2 协同机制一：生成-审核博弈回路（辩论与交叉验证）

这是赛题创新性要求的核心实现。教学子图（LangGraph StateGraph）：

```
retrieve → generate → review ──(条件边)──→ END
              ▲                  │
              └── 定向打回重写 ───┘（任意 1 条论断未获支持且未超轮次上限）
```

**机制要点**：

1. **论断级证据链**：生成输出的每条论断（claim）强制挂 `evidence_ids`（引用的知识条目 ID 列表，非空校验）与 `claim_type` 分层——审核有据可查，溯源链直通知识库原文；
2. **NLI 三分类裁决**：审核对每条论断独立裁决 `supported / partially_supported / unsupported`，并给出打回理由；幻觉的判定对齐赛题本义（专业知识谬误）——与条目矛盾或编造才计幻觉，条目未写明但事实正确的领域常识判"部分支持"（不计幻觉、不进讲义）；
3. **分级审核标准**：不同分层论断用不同严格度（见 §4.1）——证据锚点不放松（证据链照常校验），只是裁决标准按论断性质分级；
4. **定向打回**：任意 1 条论断未获支持即触发重写，但**只重写被驳回的论断**（原位替换），只复审被替换的论断——论断相互独立，整稿重写既浪费又会引入翻判（实测教训：整稿复审会把上轮已通过的论断翻判）；
5. **裁决日志模型**：`review_history` 是 append-only 裁决日志，每条论断的当前裁决 = 日志中最新一条——闸门判定、事件流展示、幻觉率指标三者同源，未改写论断的裁决天然不漂移；
6. **轮次硬上限**（2 轮）防无限辩论；超限放行时裁决已完整落库，幻觉率指标照常可复算，下游知晓"该轮教学质量存疑"。

**审核独立性红线**：审核智能体的上下文中**没有任何画像字段**——它只看"论断与证据条目"，不看学生是谁。这保证了裁决的客观性：同一份论断对任何学习者裁决一致，防幻觉论证不被个性化诉求稀释。

### 3.3 协同机制二：检验-决策回路（掌握度驱动的教学状态机）

教学不止于"讲"，还在于"验"。每个主题教学后进入检验回路：

```
出题（题型由掌握度驱动）→ 学生作答 → 判分（规则预筛 + LLM 复核）
  → 掌握度更新 → 决策：
     ├─ advance（达标）→ 资源沉淀 → 下一主题
     ├─ retry（未达标）→ 错因回流重教（上一轮题目+作答+评估注入生成端）
     ├─ regress（连续 2 次答错）→ 回前置主题降维重教
     └─ answer 失败 → 下轮先出脚手架选择题（镜像错误理解）→ 答对回回答题
```

决策由纯函数 `decide_next_step` 裁决（优先级：连错降维 > 达标前进 > 超限放行 > 重教），LLM 只承担其中的判分复核与评估措辞——**教学决策权完全在确定性代码手里**。

### 3.4 上下文隔离矩阵（防幻觉与防放水的结构基础）

多智能体协同的质量上限取决于"每个智能体看到什么"。系统为每个智能体定义了严格的读写权限，越界即视为缺陷：

| 智能体 | 可读 | 可写 |
|---|---|---|
| diagnose | 原始画像、测试结果 | 盲区清单、难度层级、画像摘要 |
| retrieve | 盲区、难度层级、锚定条目 | 检索结果、未覆盖盲区 |
| generate | 检索条目、锚定条目、**画像摘要**（非原始画像）、打回意见、错因上下文、已教论断（防复读） | 论断草稿、引用条目 |
| review | 论断草稿、引用条目、轮次 | 裁决日志、打回意见 |
| question | 条目、已教论断（出题上限）、降维信号、历史题目（防换皮重考） | 题干 + 判分要点 |
| feedback | 题目、作答、规则判分结果 | 裁决、评估、遗漏清单 |

**五条隔离红线**（不可突破）：

1. review 读不到任何画像字段（审核独立性）；
2. generate 只读画像摘要，禁止接触原始画像模型；
3. 对话日志永不进生成上下文（防学生作答污染讲义内容）；
4. 判分要点（expected）永不进学生视野（只落库供判分与审计）；
5. 交互结果只约束教学执行层，永不反向修改课程本体与切片（本体静态）。

### 3.5 协同决策中间数据的完整留痕

赛题要求提交"多智能体协同决策中间数据"。系统的统一事件流（`session_events` 表，会话内序号单调、载荷自包含）**一表三用**：

| 用途 | 消费方式 |
|---|---|
| 裁判面实时渲染 | 后端边执行边写库并推 SSE，前端逐事件渲染 |
| 回放演示 | 按序号重放同一流，前端渲染代码完全复用（评委无 LLM key 环境的可演示保障） |
| 审计日志 | 每一步决策、每一次裁决、每一次打回永久留痕，评测指标从事件流复算 |

事件协议共 20 类（`session_start` / `diagnose_done` / `plan_done` / `topic_start` / `retrieve_done` / `generate_done` / `review_done` / `teach_delivered` / `question_built` / `answer_graded` / `scaffold_offered` / `followup_asked` / `followup_offered` / `followup_graded` / `topic_advance` / `topic_regress` / `package_saved` / `packages_exported` / `session_end` / `error`），完整覆盖协同闭环的每个决策点。

## 4. 核心技术机制

### 4.1 幻觉防控体系（赛题创新性核心：四层纵深 + 量化证明）

**第一层：论断分层与证据链（生成端约束）**

生成智能体输出的每条论断必含 `evidence_ids`（非空）与 `claim_type`，三种分层对应三种教学职能与审核标准：

| 分层 | 职能 | 审核标准 |
|---|---|---|
| `core`（条目覆盖层） | 主体教学内容，按教学弧组织：概念论断（定义+类比）→ 示例论断（具体化演算示例）→ 要点论断（条目原文写明的规则） | **必须被条目原文明确支持**（逐字证据链） |
| `extension`（错因扩展层） | 仅重教轮出现：针对学生上一轮错因的应用级讲解 | 降为"概念一致 + 推导自洽"（允许推导与示例，不得引入条目之外的新概念） |
| `procedure_guide`（实操指南层） | 仅步骤类条目：操作步骤 + 可运行示例 + 检查点 | 同 extension（步骤正确性由条目锚定） |

**分级标准的意义**：赛题指出"严格限制会失去个性化"。分层审核让个性化内容（错因扩展）有受控的生存空间——证据锚点不放松（证据链照常校验、可溯源），只是裁决标准按论断性质分级；而讲义只收 `supported` 论断，交付底线不因分层而松动。

**第二层：审核裁判与定向打回（校验端博弈）**

见 §3.2。关键设计：定向打回（只重写被驳回论断）+ 裁决日志模型（当前裁决取日志最新一条）——实测修复前有论断在整稿复审中被翻判的问题，修复后同画像单会话 6 次打回全部定向修复、零翻判。

**第三层：交付过滤（出口端兜底）**

讲义只装配 `supported` 论断；`partially_supported` 与 `unsupported` 不进任何交付物。即使审核轮次超限放行，出口过滤保证学生看到的讲义永远有证据支撑。

**第四层：全链路 fail-closed**

无裁决视为未支持（计入幻觉率分子）、审核 LLM 失败回退规则检查、生成失败显式报错不静默降级——所有异常路径从严处理。

**量化证明（审核消融对照，`evals/ablation.py`）**：

打回回路的价值无需主观论证——事件流里天然躺着对照组：

| 层 | 口径 | 幻觉率 |
|---|---|---|
| 基线（无回路） | 每主题 `review_done` 首轮裁决——若系统没有打回机制，交付的就是这份初稿 | **8.86%**（361/4074 条论断） |
| 最终（有回路） | `teach_delivered` 最终裁决——打回重写后实际交付 | **0.44%**（18/4074） |

50 组会话中打回重写实际触发 **237 轮**，净挽救 **343 条幻觉论断**，相对降幅 **95.0%**。基线 8.86% 超过了赛题 <5% 的红线，最终 0.44% 远优于红线——审核回路的存在与否直接决定了是否达标。

### 4.2 知识溯源体系（高保真溯源）

溯源链贯穿四个环节：

```
知识库条目（每条标注 source 出处）
  → 论断（evidence_ids 强制）→ 审核裁决（逐条、理由留痕）
  → 讲义（仅 supported 论断，保留证据标注）
  → 导出条目（source 字段改写为生成溯源链，含审核通过率 n/m）
```

前端呈现：讲义每段落旁展示证据条目；裁判面溯源侧栏可查每条论断的引用与裁决；报告页资源卡片展示完整溯源链。

### 4.3 掌握度模型（教学决策的中枢）

掌握度数学是全链路唯一数值事实源（纯函数，全部参数集中定义，禁止散落各模块）：

| 机制 | 设计 | 目的 |
|---|---|---|
| **recency 加权** | 最近 5 次作答按新旧加权（0.5/0.7/0.85/0.95/1.0） | 早期失误后的恢复被加权补偿，不因开局连错永久惩罚 |
| **置信度封顶** | 作答 1 次上限 0.5、2 次上限 0.8 | 防"碰巧答对即通关"——证据不足绝不宣告掌握 |
| **掌握门槛 0.7** | 达到才允许前进 | 前进必须有足够证据 |
| **连错降维** | 连续 2 次答错 → 回前置主题 | 连错是"地基没打牢"的最强信号 |
| **轮次上限 5** | 超限按部分掌握放行并标注 | 防死循环 |

掌握度驱动的教学行为全景：

- **题型选择**：掌握度 <0.5 出选择题（识别式）、≥0.5 出回答题（回忆式），**单向推进**——进入回答题深度后不因单次失误降回选择题（识别题会掩盖真实理解状态）；
- **巩固模式**：回答题答对但未达门槛（仅缺证据数量）→ 跳过重复教学直接出确认题——确定性规则读历史，不改变掌握度数学；
- **进阶挑战**：主题掌握度 ≥0.85 → 资源包附加进阶挑战任务（更高难度条目的引导任务）——赛题"进阶挑战"要求的双向实现（降维 + 进阶）；
- **脚手架**：回答题失败后下一轮先出脚手架选择题，干扰项**镜像学生的错误理解**（对比中发现自己的问题），答对回到回答题、答对不计入掌握度历史（不打断连错计数）。

### 4.4 混合检索与锚定策略

教学供料采用三路策略：

1. **锚定**：当前主题的条目强制进入教学上下文（检索只作补充）——防语义相近的邻域条目带偏本轮教学；
2. **混合检索**：FTS5 全文检索（中文逐字切分，索引与查询同语义）+ sqlite-vec 向量检索（BGE-M3 本地）+ RRF 倒数排名融合，附检索覆盖度判定（盲区未覆盖显式上报）；
3. **难度闸门**：按诊断难度层级过滤条目难度上限（beginner 只看难度 ≤2 条目）——个性化从检索阶段就开始。

### 4.5 出题体系（深度契约与题型设计）

| 题型 | 生成方式 | 质量控制 |
|---|---|---|
| **回答题** | LLM 生成题干 + 判分要点（场景化提问） | ① 判分要点字符必须全部出自条目内容 ∪ 题干本身（服务端逐字校验，防编造考点）；② **深度契约**：注入该条目全部轮次的已教论断作为出题上限——学生只需运用已教概念即可作答，杜绝"教得浅、考得深"；③ 答错后重教注入降维信号——下一题只针对最重要的遗漏要点出识别级题目，深度不升反降，防"失败后题更难"的死亡螺旋；④ 注入历史题目防换皮重考 |
| **概念辨析选择题** | LLM 一次生成三件套：题干 + 陈述句正确项 + 误解干扰项 | 服务端 bigram 词重叠校验（正确项与条目 ≥2、干扰项 ≥1，防跑题）；正确项位置随机化；判分只认选项标签；校验失败回退确定性关键词构造 |
| **脚手架选择题** | 正确项 = 本轮教学论断提炼的完整陈述句；干扰项首项镜像学生错误理解 | 结构校验 + 词重叠校验 + 干扰项互异校验，失败回退确定性构造 |
| **动态追问（困惑记录）** | 学生主动提问 → 判定有效后记录困惑并直接给出解答（锚定条目+讲义，同域校验） | 不即时出题：困惑注入下一轮教学针对性讲解（错因回流同通道），并作为误区提炼原料；不写掌握度（侧车轮，不干扰主状态机） |

出题缓存语义：未作答幂等复用（页面刷新安全），已作答（无论对错）一律重新生成——原题重考测不出新理解。

### 4.6 判分级联（评估与裁决分离 + 题意核对硬收口）

回答题作答的处理链：

```
规则预筛（关键词覆盖率，审计信号）
  → LLM 复核裁决（衡量"意思"而非"用词"：实例/通俗说法表达同义判对）
  → 题意核对：强制拆"题目要求检查单"输出遗漏清单
     └─ 判对但遗漏清单非空 → 服务端硬降级为部分正确（矛盾检测）
  → 教学评估（总送 LLM——低覆盖率的作答最有教学价值）
  → 掌握度更新 → 进/停/退决策
```

设计要点：

- **评估与裁决分离**：规则预筛只降级裁决、不降级评估——覆盖率不足的作答往往最需要教学点评；
- **裁决权归属**：关键词覆盖是字符级代理指标，测不了"用实例表达同义"——同义判定权归 LLM 复核，防放水靠三层结构（矛盾检测 / 题意核对清单 / 后续轮兜底：题型单向推进 + 前进需多轮达标 + 连错降维）；
- **fail-closed 收口**：LLM 复核失败回退规则时，要求关键词 100% 覆盖才判对——无语义证据时从严格则。

### 4.7 资源沉淀与复用闭环（产出物可复用）

**资源包三形态**（按学习者 × 主题归档，跨轮合并）：

| 形态 | 内容 | 对应赛题要求 |
|---|---|---|
| 定制化讲义 | 通过审核的论断按教学弧组装，逐段挂证据链 | 定制化资源 |
| 分阶测试题 | 选择题 / 脚手架 / 回答题按轮次归档（分阶 = 掌握度驱动的题型阶梯） | 分阶测试题 |
| 实操指南 | 步骤类条目专属：步骤 + 可运行示例 + 检查点，受同一审核管线约束 | 实操指南 |

另附进阶挑战任务（掌握度 ≥0.85 主题）与难度层级标记（适配率指标输入）。

**条目化导出（产出物与知识库同构）**：资源包可提炼为与知识库条目完全同构的结构——讲义论断经**导出三重过滤**后拼接为条目正文：① 剔除错因扩展论断（面向当前学生错因的定向讲解）；② 剔除含学习者指涉的个性化措辞（可复用知识必须与学习者无关——讲义保留这些内容是教学功能，入库形态收口过滤）；③ 跨轮换皮去重（同一知识不同说法只留一份）。错题/脚手架原料经 distill 智能体提炼为知识化误区段落——提炼的输入/输出同样受控：个性化评估文本不进提炼上下文（防学习者措辞被复读），每条误区必须标注讲义出处（"正确理解"取材自审核通过的讲义论断，服务端锚定校验，锚不上即弃）；题目本身不进库——它们是教学过程数据不是知识，导出条目继承源条目的前置关系/难度/知识类型，溯源链写入 source 字段。导出经四重自检（结构校验 + 关键词子集校验 + 无学习者指涉 + ID 唯一）后可被初始化脚本**原样入库**——"系统生产的资源喂回系统"的硬证明，也是"资源生产引擎"定位的闭环论证。

导出管线同时提供 Web 主动触发端点与文件下载，报告页与资源库页均可查看导出条目本体。

## 5. 数据层设计

### 5.1 领域知识库切片（测试数据之一）

主演示领域为**大数据工程技术人员（初级·大数据分析方向）**，取材国家职业技术技能标准（2021 年版）的条目骨架，正文经 SQL/pandas 官方文档与经典教材理解性改写（禁直接复制，版权合规），每条标注来源出处。

知识库切片共 **31 条**条目，构成带前置依赖的有向无环图：

| 维度 | 分布 |
|---|---|
| 知识模块 | SQL 查询 10 · Python 数据处理 6 · 统计基础 5 · 数据表/仓库 4 · 可视化 3 · 数据库基础 2 · 工作流 1 |
| 难度梯度 | 1 级 4 条 · 2 级 6 条 · 3 级 12 条 · 4 级 7 条 · 5 级 2 条 |
| 知识类型 | 步骤技能（procedure）15 · 概念关系（concept）14 · 事实术语（memory）2 |

每条条目包含：ID / 标题 / 正文（50-100 字）/ 关键词 / 前置条目 / 难度 / 知识类型 / 来源。**知识类型描述知识本体**（影响教学方式与指南生成），不绑定题型——题型只由掌握度驱动。

条目质量由自动化校验闭环保障：关键词的每个字符必须出现在正文中（判分靠子串匹配，防判分失配）、前置依赖存在且难度单调、依赖图无环——全量校验落为单元测试，任何一条不合格即测试失败。

### 5.2 数据库设计（SQLite 单文件，9 张表）

全部表结构幂等迁移（检查列 → 缺失则增补），禁止删库重建——知识库与运行数据共存于 `data/knowledge.db`：

| 表 | 职责 | 关键设计 |
|---|---|---|
| `knowledge_entries` | 领域知识库本体 | 附 FTS5 全文索引表 + sqlite-vec 向量表（rowid 对齐） |
| `learner_profiles` | 画像种子（只读） | 本体静态原则：运行时永不修改 |
| `sessions` | 会话元数据 | 画像完整快照 + 诊断结果 + 切片，一次诊断永久留痕 |
| `session_events` | **统一事件流（一表三用）** | 会话内序号单调递增 + 载荷自包含：同时服务裁判面实时渲染、回放演示、审计日志 |
| `topic_rounds` | 教学轮快照 | 题目/作答/判分/决策的结构化中间数据——即赛题要求的"协同决策中间数据"；判分要点单列存储，永不进学生视野 |
| `mastery_snapshots` | 掌握度历史 | 每次作答后的掌握度轨迹：报告曲线与跨会话延续的数据源 |
| `resource_packages` | 资源包（赛题主交付物） | 三形态资源 + 难度层级 + 溯源链；按（会话×条目）唯一，跨教学轮智能合并（讲义追加、题目按题号去重） |
| `exported_entries` | 条目化导出产物 | 与知识库同构的生成条目本体 + 源条目溯源列 |
| `learners` | 学习者档案 | 测试数据导入时的画像归属 |

### 5.3 事件协议与会话状态机

事件协议 20 类（§3.5），每类事件载荷自包含——前端仅凭事件流即可完整渲染整个协同过程，不依赖任何额外查询。

教学轮状态机（会话编排服务实现，CLI 与 Web 共用同一入口）：

```
主题开始 ─→ 教学（子图：检索→生成→审核，定向打回 ≤2 轮）
        ─→ 出题（选择 | 脚手架 | 回答，题型底线单向推进）
        ─→ 作答 ─→ 判分级联（规则预筛 → LLM 复核 → 题意核对硬收口）
               ├─ advance ─→ 资源沉淀 ─→ 下一主题（或会话结束）
               ├─ retry   ─→ 下一教学轮（错因上下文注入生成端）
               ├─ regress ─→ 回前置主题（降维重教）
               └─ 脚手架待答 ─→ 脚手架题 ─→ 答对回回答题 / 答错计一次错
```

**进度全部从历史推导**：会话没有任何内存态——是否已教、是否脚手架待答、重教上下文、巩固模式判定，全部由教学轮与掌握度历史计算得出。进程随时重启、页面随时刷新，状态无损恢复。这是后端无状态、前端可任意恢复的工程基础。

## 6. 前端展示层设计

前端共 **7 个画面**，覆盖学习者、培训管理者、评审三类视角：

| 画面 | 路由 | 职责 |
|---|---|---|
| 产品落地页 | `/` | 系统定位、协同管线流程图、三指标实测数字与消融对照 |
| 画像输入 | `/` 与 `/sessions/new` | 画像表单（教育背景/经验/目标/初始掌握度），内置两组差异化预设一键填充 |
| 学生面导学工作台 | `/sessions/{id}` | 流式教学渲染 + 答题交互 + 追问面板 |
| 裁判面协同调度 | `/sessions/{id}/orchestration` | React Flow 多智能体调度图（live 实时跟随 / replay 播放器双模式） |
| 学情报告 | `/sessions/{id}/report` | Recharts 三图 + 资源包浏览 + 条目化导出入口 |
| 资源库 | `/resources` | 跨会话聚合：全部资源包与导出条目，会话/条目双筛选 |
| 会话列表 | `/sessions` | 历史会话入口（回放/报告/删除管理） |

### 6.1 学生面导学工作台（交互导学体验）

三栏布局，核心教学交互全程免滚动：

- **讲义区（堆叠卡牌轮播）**：论断逐条聚焦展示——主卡聚焦当前论断，下方露出下一张卡的错开边缘作视觉暗示；切换通道多通道化（键盘方向键 / 卡片左右边缘点击区 / 暗示卡），方向感知动画；
- **作答区**：题目卡片 + 作答输入 + 判分反馈（判定、覆盖率审计信号、教学评估、遗漏清单）；
- **追问面板（Popover 按需唤起）**：学生可随时对当前内容提问——有效疑问由系统记录困惑并直接给出解答，下一轮教学针对性强化（详见 §4.5）；面板收敛为触发入口，最近困惑记录刷新可恢复。

### 6.2 裁判面（多智能体协同调度可视化，赛题核心画面）

React Flow 有向图呈现协同闭环的实时状态：

- **三条泳道**：① 诊断与切片 / ② 教学子图（检索→生成→审核）/ ③ 检验与决策；
- **打回回路可见**：审核驳回 → 定向重写 → 复审的回路以独立回边呈现，每次裁决结果落节点徽章；
- **多通道边路由**：同源同靶的多条边（生成↔审核双向、前进/降维双回边）经隐藏锚点分离，无重叠遮挡；
- **证据溯源侧栏**：逐条论断的引用条目与裁决理由；
- **双模式**：live 模式经 SSE 实时跟随另一标签页的进行中会话；replay 模式为步进/倍速播放器——评委无 LLM key 环境的完整演示保障。

### 6.3 学情报告（三图 + 资源 + 指标）

对应赛题要求的三图：

| 图 | 实现 | 设计要点 |
|---|---|---|
| **知识盲区雷达** | Recharts RadarChart | 每主题掌握度一轴；轴标签全局唯一消歧（防渲染撕裂）；达标段掌握度用 ease-out 映射贴近满半径（达门槛即前进，0.7~1.0 的差异教学决策层无意义）；门槛虚线圈标示 0.7 |
| **资源-难度匹配** | 逐包层级明细 | 每个资源包的难度层级与诊断层级对照（适配率指标的可视化） |
| **学习路径规划图** | React Flow | 主题序列 + 前进边 + 降维回边（同主题多次回退自动去重）；主题多时横向滚动 |

报告页同屏呈现：赛题三指标总览（口径与评测脚本同源）、三形态资源包浏览（讲义逐段证据标注、分阶题、实操指南、进阶挑战）、知识库同构导出条目本体、条目化导出触发与下载。

### 6.4 实时与回放同构（事件流驱动）

实时会话中后端边执行边写事件流并推 SSE；回放按序号重放同一流——**前端渲染代码完全复用**，一套组件同时服务两个模式。这意味着：演示视频的每个画面、评委自己导入的测试数据、审计追溯，看到的都是同一份事实。

## 7. 评测体系与实测结果

### 7.1 三指标口径（单一事实源：`evals/metrics.py`）

三项指标全部**规则可复算、不依赖人工打分**——评测脚本一遍跑出全部数字：

| 指标 | 赛题目标 | 口径 |
|---|---|---|
| 幻觉率 | <5% | 最终裁决为未支持的论断数 / 总论断数（无裁决视为未支持，fail-closed 从严） |
| 画像-资源适配率 | ≥85% | 资源包难度层级与诊断难度层级的匹配率（含 ±1 层容忍带——相邻层级的适配属合理区间） |
| 知识点覆盖率 | ≥90% | 目标条目的关键词在该条目资源包讲义文本中的覆盖比例（逐条目聚合） |

### 7.2 测试方案：50 组差异化画像

画像设计遵循科学性三原则：

- **难度分布**：beginner / intermediate / advanced 各档均衡，每档 5 种经验模板变体（共 15 个变体 × 扩展）；
- **初始掌握度梯度**：与经验档自洽注入（零基础无先验掌握度；中级 1-3 条基础条目 0.55-0.8；高级 2-4 条中高级条目 0.7-0.95）——掌握度进入诊断上下文，高掌握条目不应再被诊断为盲区；
- **防趋同**：固定随机种子的可复现生成器，3 组手工精设演示画像 + 47 组程序生成。

批跑工程：并发限流、逐组落盘、断点续跑、每组独立随机流——50 组全量跑批可一键复现。

### 7.3 实测结果（50 组全量归档）

| 指标 | 赛题目标 | **实测** | 结论 |
|---|---|---|---|
| 幻觉率 | <5% | **0.44%** | ✅ 优于目标一个数量级 |
| 画像-资源适配率 | ≥85% | **99.0%** | ✅ |
| 知识点覆盖率 | ≥90% | **97.2%** | ✅ |
| 掌握度均值 | — | 0.7112 | 达门槛水平 |
| 论断总量 | — | 4074 条 | 统计充分 |
| 打回重写触发 | — | 237 轮 | 审核回路真实高频工作 |

### 7.4 审核消融对照（回路价值的量化证明）

见 §4.1 详述：**无打回回路的裸幻觉率 8.86%（超赛题红线）→ 有回路 0.44%，净挽救 343 条幻觉论断，相对降幅 95.0%**。该对照无需关闭审核重跑系统——首轮裁决与最终裁决同存于事件流，是"打回重写值多少分"的直接证据。

### 7.5 完整输入输出示例（交付包随附）

测试数据包包含 **50 组全量会话示例**，每组五类文件完整对应赛题要求：

| 文件 | 对应赛题要求 |
|---|---|

| 协同决策中间数据-事件流 | 多智能体协同决策中间数据 |
| 出题判分轮次明细 + 掌握度轨迹 | 协同决策中间数据（结构化） |

配套 **测试数据导入器**（`scripts/import_test_data.py`）：一键将示例数据灌入数据库，前端会话列表/回放/报告页即可直接浏览全部 50 组会话——**评委无需 LLM key 即可完整审阅所有输入输出示例**。

### 8.4 数据合规

- 画像与交互数据**全部本地 SQLite 存储**，无任何第三方上报；
- 演示与评测数据均为**虚构画像**（程序生成的职业背景与测试成绩）；
- 知识库内容来自公开国家标准与官方文档的理解性改写，每条标注溯源出处，无版权侵权内容；
- LLM 调用仅传输教学所需的最小上下文（画像摘要而非原始画像——隔离红线同时也是最小化数据暴露）。

### 8.5 领域泛化与可迁移能力（实用价值论证）

三层论证，全部有实现支撑：

1. **换目录即换领域**：知识库是纯数据文件（`data/seeds/<domain>/entries.jsonl`），代码零改动切换领域——领域知识只通过条目结构（正文/关键词/前置/难度/知识类型）与系统交互；
2. **产出物与知识库同构**：系统生成的资源可原样回流入库（§4.7）——迁移到新领域后，系统产出的资源同样可沉淀复用，引擎属性不因领域改变而削弱；
3. **个性化机制与领域无关**：掌握度数学、题型阶梯、审核管线全部作用于"条目-论断-裁决"的抽象层，不含任何领域硬编码。
