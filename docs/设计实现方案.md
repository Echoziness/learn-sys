## 摘要

本作品是一套面向职业培训场景的学习资源生产系统。系统以学习者画像为输入，通过一次导学会话完成学情诊断、逐主题教学与作答检验，产出定制化讲义、分阶测试题、实操指南三种形态的个性化资源包以及学情报告。与单一模型直接生成的方案不同，系统将内容生成与质量裁决分离到不同职责单元：生成输出的每一条论断必须携带知识库出处，由独立的审核单元逐条核对，未通过的内容退回重写，无法修复的内容在交付出口拦截。在 50 组不同背景学习者画像的全量测试中，交付内容的幻觉率为 0.44%，画像与资源难度的适配率为 99.0%，知识点覆盖率为 97.2%，均优于赛题设定目标。对照事件流中保留的首轮审核记录，审核回路的收益可以直接量化：若不启用退回重写，幻觉率为 8.86%，高于赛题 5% 的红线。

## 1 背景与问题

大模型用于职业培训资源生成时有两个绕不开的问题。

第一是幻觉。职业培训的内容直接对应岗位操作规范，一段编造的步骤或错误的参数可能误导实际操作。通用大模型在缺少专业知识约束时，会为了行文流畅而补造细节，这在培训场景不可接受。

第二是个性化与质量控制的矛盾。要让内容贴合学习者，就需要放开模型的生成自由度；要控制质量，就需要收紧约束。单一模型同时承担这两个目标时，结果是两头妥协：要么内容准确但千篇一律，要么贴合学情但夹带错误。

我们的处理思路是把这两个职责拆开。模型负责生成贴合学情的表述，一套独立于生成过程的机制负责核对每一句话是否有知识库出处。导学会话因此具有双重身份：对学习者而言它是一次个性化教学，对培训机构而言它是资源的生产过程。会话中通过审核的内容实时沉淀为资源包，同一知识库配合不同画像会产出不同的资源，产出的资源经过提炼还可以回流入库供后续会话使用。

## 2 目标与非目标

目标：

- 同一领域知识库下，不同画像的学习者获得不同的三形态资源包，且资源难度与诊断结论匹配
- 幻觉率可测量、可复算，不依赖人工抽查
- 协同过程的每一步决策与裁决留痕，支持回放与审计
- 评委环境零外部依赖可部署：无向量模型、无 LLM 密钥时仍可启动并回放全部示例会话

非目标：

- 不做自由问答聊天。所有教学内容必须能对应到知识库条目，无法对应的提问只作有限解答并记录，不作为教学资源沉淀
- 不允许交互结果修改知识库与课程切片。本体数据在会话期间只读，保证同一画像的诊断与切片可复现
- 不预设 LLM 厂商。系统只依赖 OpenAI 兼容协议，更换模型仅需修改配置
- 不引入 SQLite 之外的存储组件。检索（全文与向量）、会话、资源包全部落在一个数据库文件内

## 3 总体设计

### 3.1 运行形态

系统的运行态由三部分组成：一个 Python 进程（后端，含多智能体编排与检索）、一个 Node 进程（前端）、一个 SQLite 数据库文件。除此之外没有任何外部服务。知识库、全文索引、向量索引、会话数据、资源包全部存于这一个文件，拷贝即迁移。

依赖方向是单向的：前端通过 SSE 与 REST 调用后端，后端调用教学内核，内核读写数据库并访问外部 LLM 接口。后端 API 层只做序列化与推流，不含业务逻辑；内核不接触网络层。

前端提供三个功能画面：学生面的导学工作台（教学交互）、裁判面的协同调度可视化（多智能体运行状态与裁决过程）、报告页（学情三图与资源包浏览），另有会话列表与资源库两个导航辅助页。实时会话与历史回放共用同一套渲染组件，回放时不需要 LLM 密钥。

### 3.2 一次会话的处理流程

学习者提交画像后，会话按以下流程执行：

诊断智能体读取画像，输出知识盲区清单与难度层级。诊断调用使用零温度参数，同一画像的诊断结果可复现。盲区清单随后进入课程切片：将盲区投影到知识库条目，补全全部前置依赖条目，按画像难度过滤，最后做拓扑排序得到教学顺序。切片过程是纯函数，不涉及模型调用。

切片中的每个主题依次进入教学子图。子图由三个节点组成：检索为当前主题召回补充材料，生成节点产出带出处的教学论断，审核节点逐条裁决。未通过裁决的论断退回生成节点定向重写，重写后只复审被替换的部分。

教学交付后进入检验环节。系统按当前掌握度出题（低掌握度出选择题，达到阈值后出回答题），学生作答后由规则判分与模型复核共同给出判定，掌握度随之更新，并决定下一步动作：达标则进入下一主题；未达标则以学生的错因为素材重教；连续两次答错则回到前置主题重新讲解。每个教学轮次通过审核的内容同步写入资源包。

会话结束时生成学情报告，资源包可导出为与知识库同构的条目，回流入库。

### 3.3 技术选型与理由

多智能体编排使用 LangGraph。教学子图中审核到生成的退回是一条条件边，图模型可以直接表达；诊断、切片等环节则在图外以普通函数调用，不强行纳入图结构。

存储与检索使用 SQLite 全家桶：业务数据用普通表，全文检索用 FTS5 扩展，向量检索用 sqlite-vec 扩展。选择单文件方案的原因是把部署面压到最小，评委环境不需要安装任何数据库服务。向量数据库（如 Chroma）会引入第二个存储组件，被否决。

Embedding 模型使用 BGE-M3 本地部署，随交付包携带。检索链路完全离线，评测批跑不产生任何调用成本，评委只需要一个 LLM 密钥。

前端使用 Next.js 15 与 TypeScript 严格模式，协同调度图用 React Flow 渲染，学情图表用 Recharts 渲染。

后端使用 FastAPI。会话事件通过 SSE 单向推送，比双向通道实现量更小。

交付形态为本地部署。系统曾完整实现过容器化方案，评估后放弃：容器化对评委环境增加了安装 Docker 与配置构建网络两道门槛，而两进程加一个文件的形态本地部署失败面更小。

## 4 多智能体协同体系

### 4.1 职责划分

系统共有九个职责单元，其中六个调用大模型，三个为确定性纯函数。划分原则是：语言与语义判断交给模型，策略与数值决策交给代码。

| 职责单元 | 职责 | 类型 |
|---|---|---|
| 学情诊断 | 画像转换为盲区条目清单与难度层级 | 大模型，零温度 |
| 证据检索 | 锚定当前主题条目并召回补充材料，按难度过滤 | 确定性 |
| 领域知识生成 | 依据条目与画像摘要产出带出处的教学论断 | 大模型 |
| 审核裁决 | 逐条论断核对出处，给出三类裁决与退回意见 | 大模型，规则兜底 |
| 出题 | 生成回答题、选择题、脚手架题，判定并解答学生追问 | 大模型，服务端校验 |
| 判分复核 | 作答的概念级判定与教学评估 | 大模型，规则兜底 |
| 误区提炼 | 从错答记录提炼可入库的误区知识 | 大模型，服务端校验 |
| 切片、题型选择、掌握度 | 课程排序、题型决定、数值计算与进退决策 | 纯函数 |
| 资源组装 | 三形态资源包的装配、归档与条目化导出 | 纯函数 |

### 4.2 生成与审核的协同

生成与审核通过一个带退回的循环协同。生成节点输出的每条论断必须携带引用的知识条目编号，审核节点以条目原文为依据逐条裁决，裁决分三类：支持、部分支持、不支持。判定为不支持的论断连同退回意见返回生成节点重写，重写只替换被驳回的论断，复审也只针对被替换的部分。审核最多两轮，保证循环必然终止。

审核单元的上下文中不包含任何学习者画像信息。同一份论断对不同学习者的裁决结果一致，质量裁决不被个性化诉求影响。

### 4.3 检验与决策的协同

教学交付后，出题、判分、掌握度更新、进退决策构成第二个循环。这个循环里模型只承担两件事：生成题目文本，以及复核回答题作答的语义。其余全部是确定性代码：出什么题型由掌握度数值决定，答对答错之后的进退由决策函数裁决。这样安排的原因是把教学策略从模型的不确定性中剥离出来，策略行为可以单元测试，出现争议时可以逐步回放事件流定位。

### 4.4 上下文隔离

每个职责单元能读取和写入的状态都有明确定义，超出定义即视为缺陷。其中有四条边界是不可突破的：

审核单元读不到任何画像字段；生成单元只能读画像摘要，读不到原始画像；学生的作答记录不会进入讲义生成上下文；判分要点只存于服务端数据库，不会出现在学生可见的任何界面。

这些边界同时服务于两个目的：防幻觉（生成与审核都锚定在条目上，不被对话内容带偏）与数据最小化（传给外部模型接口的上下文越少越好）。

### 4.5 协同过程留痕

全部协同过程记录在统一事件流中。事件流是数据库里的一张表，会话内序号单调递增，每条事件的载荷自包含。同一份数据服务三个用途：裁判面实时渲染（后端边执行边推送）、回放演示（按序号重放）、审计与指标复算（评测脚本直接从事件流聚合）。前端渲染实时与回放两种模式用的是同一套组件，因此评委在回放里看到的过程与真实运行完全一致。

事件协议共二十类，覆盖诊断、切片、教学、裁决、出题、作答、决策、资源沉淀、导出与会话生命周期。

## 5 关键技术机制

### 5.1 幻觉防控

防控机制需要满足两个条件：每一条生成内容都能独立判定对错；判定过程本身可以被复核。同时，防控不能以消灭个性化为代价。针对学生错因的补充讲解是个性化的主要来源，这类内容天然超出知识库原文，如果一律按无出处即拦截处理，重教环节将没有内容可讲。

备选方案的对比如下。仅靠提示词要求模型引用出处，无法独立验证，模型可能伪造出处，幻觉率不可测量。对整篇讲义做一次整体审核，则无法把幻觉定位到具体论断，退回时只能整稿重写，已通过的内容会被重新审核并可能改判。本系统采用逐条证据链加逐条裁决：每条论断独立挂出处、独立受审、独立退回。

生成端，论断分三层。主体教学内容要求与条目原文逐字对应；错因补充讲解允许推导和示例，但不得引入条目之外的新概念；实操步骤要求步骤本身能对应到条目。三层使用不同的审核标准，但出处校验一视同仁。分层的原因如上：如果三层使用同一标准，错因讲解会全部被拦截；而分层后个性化的内容有受控的生存空间，交付底线不因此松动。

审核端采用自然语言推理的三分类形式：以条目原文为前提，以论断为假设，判定二者的推理关系。裁决结果、理由、轮次全部写入事件流。

交付端，讲义只装配判定为支持的论断。模型调用失败时的兜底规则从严判定，宁可少交付，不交付无法核实的内容。

审核回路的价值可以直接测量。事件流同时保留了每条论断的首轮裁决和最终裁决，首轮裁决等价于没有退回机制时系统会交付的内容，构成对照组，不需要关闭系统重新实验。50 组会话共 4074 条论断的对照结果：

| 口径 | 幻觉论断 | 幻觉率 |
|---|---|---|
| 首轮裁决（无回路） | 361 | 8.86% |
| 最终交付（有回路） | 18 | 0.44% |

退回重写共触发 237 轮，挽回 343 条幻觉论断。

### 5.2 知识溯源

溯源链贯穿四个环节：知识库条目本身标注来源出处；论断携带引用条目编号；审核裁决逐条留痕；讲义按论断保留证据标注，学生看到的每段内容都能查到出处。资源导出时，溯源链随条目一起写入，包括该条目经历了几轮审核、通过比例。前端在讲义旁、裁判面侧栏、报告页三处呈现溯源信息。

### 5.3 掌握度模型

掌握度是一个 0 到 1 之间的数值，是整个系统中枢的决策依据。它的计算只依赖学生的作答历史：取最近五次作答，按新旧赋予不同权重（越新的作答权重越高），得到当前掌握度。在此之上有三条规则：作答次数不足时掌握度有上限（答过一次最高 0.5，两次最高 0.8），防止偶然答对即宣告掌握；达到 0.7 才允许进入下一主题；连续两次答错则回到前置主题重新讲解。全部计算集中在一个纯函数模块中，其余代码不允许自行实现掌握度逻辑。

掌握度驱动四类教学行为。题型选择：掌握度低于 0.5 出选择题（识别式），达到后出回答题（回忆式），且进入回答题后不因单次失误退回选择题，避免识别题掩盖真实理解状态。巩固模式：回答题答对但证据次数不足时，跳过重复教学直接出确认题。脚手架：回答题答错后下一轮先出一道选择题，其中错误选项取材于学生刚才的错误理解，帮助学生对比发现自己的问题；脚手架答对回到回答题，且不计入掌握度历史。进阶挑战：掌握度达到 0.85 的主题在资源包中附加更高难度的引导任务。降维与进阶两个方向均由掌握度数值自动触发。

### 5.4 出题与判分

回答题由模型生成题干与判分要点，随后经过服务端校验：判分要点的每个字符必须出自条目内容或题干本身，防止模型编造考点；题目深度以该主题已交付的教学内容为上限，不允许考未教过的内容；学生答错后重新出题时注入遗漏要点信息，新题只针对最重要的遗漏，难度不升反降。

选择题考查概念辨析：模型一次生成题干、正确陈述与误解干扰项，服务端用词重叠校验确认选项与条目相关，校验失败时回退到基于条目关键词的确定性构造。判分只认选项标签，正确项位置随机。

回答题作答的判分分两级。先由规则计算判分要点的覆盖率，作为审计信号；再送模型复核，复核标准衡量的是意思而非用词，学生用实例或通俗说法表达正确理解时判对。模型同时输出一份题目要求检查单，如果判定为对但检查单显示有遗漏，服务端强制降级为部分正确。模型调用失败时回退规则判分，此时要求要点全部覆盖才判对。

学生可以随时对当前内容提问。有效疑问会被记录并给出解答，未消化的疑问注入下一轮教学的生成上下文，同时作为误区提炼的原料。追问不影响掌握度，不参与进退决策。

### 5.5 检索与知识供料

每个主题的教学供料分三路。当前主题的条目锚定进入上下文，不依赖检索结果；在此基础上做混合检索补充材料，全文检索（FTS5，中文按逐字切分建立索引）与向量检索（BGE-M3 本地编码）并行，用倒数排名融合两路结果；最后按诊断难度过滤，低难度画像不会检索到高难度条目。盲区在知识库中没有对应条目时，系统显式上报未覆盖，不做模糊匹配。

### 5.6 资源沉淀与复用

资源包按学习者与主题归档，包含三种形态：定制化讲义（通过审核的论断组装）、分阶测试题（各轮次的选择题、脚手架与回答题）、实操指南（步骤类条目专属，含步骤、示例与检查点）。跨教学轮次合并时讲义追加、题目按题号去重。

资源包可以导出为与知识库条目完全同构的结构。导出过程做三重过滤：剔除面向当前学生错因的讲解内容；剔除含学习者指涉的措辞，因为可复用的知识必须与具体学习者无关；跨轮次去除同一知识的不同表述。错答记录经误区提炼智能体转化为知识化的误区段落，每条误区必须能对应到讲义出处，对应不上的丢弃。导出前经过结构校验、关键词校验、指涉检查与编号唯一性检查四道自检，通过后可直接作为知识条目入库。系统的产出因此可以回流入库再次使用，这是资源生产引擎定位的闭环。

## 6 数据层设计

### 6.1 领域知识库

系统当前内置两个领域的知识库，用于验证领域可迁移性。主领域为大数据工程技术人员（初级，大数据分析方向），取材国家职业技术技能标准（2021 年版）的条目骨架，正文经官方文档与经典教材理解性改写，共 31 条；第二领域为 Linux 运维，共 18 条，由相同规范编写，用于验证更换知识种子目录即可切换教学领域。两个领域共 49 条，每条包含编号、标题、正文（50 至 100 字）、关键词、前置条目、难度、知识类型与来源，条目间的前置依赖构成有向无环图。

条目质量由自动化测试保障：关键词的每个字符必须出现在正文中（判分依赖子串匹配）、前置依赖存在且难度单调、依赖图无环，任何一条不合格即测试失败。

### 6.2 数据库

单个 SQLite 文件承载九张表：知识条目及其全文索引与向量索引、学习者画像种子、会话元数据（含画像快照与诊断切片）、统一事件流、教学轮次记录（题目、作答、判分、决策的结构化中间数据，即赛题要求的协同决策中间数据）、掌握度历史、资源包、导出条目、学习者档案。表结构的变更通过幂等迁移完成，运行时数据不因结构升级丢失。

会话没有任何内存状态。是否已教、是否有待答题目、重教上下文等信息全部由数据库历史记录推导，进程随时重启、页面随时刷新，会话状态无损恢复。

## 7 评测体系与结果

### 7.1 指标口径

三项指标全部由评测脚本规则化计算，不依赖人工打分。幻觉率为最终裁决不支持的论断占总论断的比例，无裁决按不支持计；适配率为资源包难度层级与诊断层级的匹配比例，相邻层级算匹配；覆盖率为目标条目的关键词在对应讲义文本中出现的比例。口径定义与单元测试共用同一份代码，报告页展示的数字与评测归档同源。

### 7.2 测试方案

50 组学习者画像覆盖三档难度层级，每档含五种经验背景变体，初始掌握度与经验背景自洽注入（零基础画像无先验掌握度，高级画像在部分中高级条目上有较高掌握度）。画像由固定随机种子的生成器产出，可复现。批跑支持并发限流与断点续跑，50 组会话的完整输入输出（画像、诊断切片、事件流、轮次明细、资源包、指标明细）全部归档随交付包提交。

### 7.3 结果

| 指标 | 赛题目标 | 实测 |
|---|---|---|
| 幻觉率 | 低于 5% | 0.44% |
| 画像与资源难度适配率 | 不低于 85% | 99.0% |
| 知识点覆盖率 | 不低于 90% | 97.2% |

50 组会话共产出 4074 条论断，掌握度均值 0.7112，达到前进门槛。审核回路的消融对照见 5.1 节。

## 8 工程交付

### 8.1 质量基线

系统共 222 个自动化测试全部通过，覆盖掌握度计算、出题判分、审核闸门、课程切片、知识条目全量校验、事件流读写、导出自检等模块。静态检查方面，Python 代码经 ruff 与 pyright 双重检查零错误，前端经 TypeScript 严格模式、ESLint 与构建检查零错误。针对赛题特别要求的两类测试：多智能体协同调度逻辑（审核闸门、退回路由、上下文隔离）与领域知识生成准确性（判分级联、种子数据校验），均有专门用例随源码交付。

### 8.2 部署与降级启动

部署形态为两个进程加一个数据库文件。交付包解压后自带预构建数据库（含全部 50 组评测会话），安装依赖后即可启动回放全部会话，不需要初始化数据库、不需要向量模型、不需要 LLM 密钥。

系统在启动时探测环境完整性，缺少组件时按能力分级启动：缺少向量模型或 LLM 配置时，回放、报告、资源浏览等只读功能正常服务，教学功能接口返回明确的缺失说明；页面顶部横幅展示当前缺少什么、影响哪些功能、如何补齐。这一设计保证评委在任何环境下都能完成评审所需的核心操作。

部署已在干净的 Windows 环境从零复现验证，交付包附带面向零命令行经验用户的分步说明。

### 8.3 提交包构成

| 组成 | 内容 |
|---|---|
| 提交包（单个压缩包） | 源码、双域知识种子、预构建数据库、50 组完整输入输出示例，解压即启动 |
| 模型文件 | BGE-M3 本地 Embedding，随包提供下载链接 |
| 部署说明 | 分步指引，每步附成功标志 |
| 清单 | 版本指纹、校验结果、评委最短操作路径 |

### 8.4 数据合规

画像与交互数据全部存于本地 SQLite，无第三方上报。演示与评测使用的画像全部为虚构数据。知识库内容来自公开标准与官方文档的理解性改写，每条标注来源。传给外部模型接口的上下文中，画像仅以摘要形式出现，不传输原始画像数据。

### 8.5 领域泛化

系统的领域知识只通过条目结构与代码交互，更换领域只需要新增一个知识种子目录并初始化，代码零改动。这一点不是设计层面的论证，而是已经验证的事实：Linux 运维领域作为第二领域完成了相同的种子编写规范校验，并可以正常建立会话、诊断、教学。掌握度计算、题型阶梯、审核管线均作用于条目与论断的抽象层，不含领域硬编码；系统产出的资源与知识库同构，迁移到新领域后同样可以回流入库。

## 9 局限与展望

系统存在几个明确的边界。其一，教学质量依赖知识库本身的覆盖度与条目编写质量，知识库未覆盖的盲区只能如实上报，不能生成。其二，审核的裁决标准依赖模型对条目原文的理解能力，极端改写（换一种说法表达相同事实）可能被误判为不支持，当前的缓解手段是退回重写而非修改裁决标准。其三，掌握度模型以作答对错为唯一证据来源，学习者的阅读行为、停留时长等信号尚未纳入。其四，单个会话的教学深度受限于条目粒度，条目切分过粗时个性化空间会收窄。

可继续推进的方向包括：多领域的跨域联合检索、基于学习行为信号的掌握度建模、资源包导出条目的自动质量分级。
