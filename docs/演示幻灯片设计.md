# 演示幻灯片设计（PPT 制作参考）

> **用途**：10 分钟评审演示的逐页设计指引——每页给出标题、信息点、视觉布局、旁白要点与数据来源。
> **叙事主线**：一条有起承转合的故事线——**矛盾（为什么做）→ 引擎（怎么做）→ 博弈（凭什么可信）→ 证据（做出了什么）**。
> **语言纪律**：面向非技术背景评委讲核心思想，技术细节只做支撑；每页只留一个核心记忆点。
> **全文依据**：`docs/设计实现方案.md`（详细版）、`docs/赛题.md`（评分标准原文）。

## P1 · 开场：一句话定位（45"）

**标题建议**：`让大模型生产"可审计"的学习资源`
副标题：learn-sys · 个性化教学暨学习资源生产引擎

**核心信息点**（只放三行）：
- 职业培训资源开发：传统方式高耗能（人工编写讲义/出题/指南）
- 大模型能按需生成——但它会**胡说**，且"迎合学生"与"专业准确"天然冲突
- 我们的回答：**多智能体协同的生产引擎**，导学会话即生产过程

**视觉布局**：深色底大字定位句居中；下方一排小图标三元素（学习者画像 → 多智能体齿轮 → 三形态资源包）。不放任何架构图——开场只立概念。

**旁白要点**：
> "赛题问的是：怎么把大模型从通用聊天工具，变成懂专业、能落地的教育资源基础设施。职业培训的资源开发是典型的高耗能环节——一位讲师为一批学员写讲义、出分阶题、编实操指南。大模型让'按需生成'成为可能，但它有两个致命问题：会幻觉，以及——放开限制去迎合学生就失去准确性，管得太死又失去个性化。我们的作品用多智能体协同同时解决了这两件事。"

**数据来源**：赛题原文背景段（`docs/赛题.md` 三.1）；产品定位（`docs/产品需求文档.md` §1）。

## P2 · 悬念：一组对照数字（45"）

**标题建议**：`没有审核回路，幻觉率 8.86%——超过赛题红线`

**核心信息点**：
- 左：**8.86%**（无打回回路时的"裸幻觉率"，超过赛题 <5% 红线，标红）
- 右：**0.44%**（审核回路实际交付，远低于红线，标绿）
- 中间一个箭头："打回重写回路挽救了 343 条幻觉论断"
- 底部一行小字悬念："这个对照不是估计值——它是系统运行中天然留下的两组账本，后面会讲"

**视觉布局**：全页只放这两个大数字 + 一根带箭头的转化轴。数字字号占版面 1/3。这是全片第一个记忆点。

**旁白要点**：
> "先看结果制造一个问题：我们让系统'假装没有审核机制'算了一遍幻觉率——8.86%，超过赛题 5% 的红线。而审核回路工作时的实际交付是 0.44%。也就是说，**审核机制的存在与否，直接决定这套系统达不达标**。它是怎么工作的、这个数字怎么来的，是接下来十分钟的主线。"

**数据来源**：`evals/results/ablation.json`（口径脚本 `evals/ablation.py`：基线 = 4074 条论断的首轮裁决 361 条未支持；最终 = 交付裁决 18 条未支持）。

## P3 · 系统全景：一台电脑的引擎（1'00"）

**标题建议**：`四层架构：两个进程 + 一个文件`

**核心信息点**：
- 四层堆叠图（自下而上）：数据层（SQLite 单文件）→ 教学内核层（智能体 + 纯函数）→ 会话服务层（API + 事件流）→ 决策可视化层（三画面）
- 右侧一句话："模块化单体——没有微服务、没有消息队列、没有额外组件"
- 角标：检索全离线（本地 BGE-M3）· 仅 LLM 调用需网络

**视觉布局**：左侧四层色块堆叠（配色与架构图一致），右侧三个极简图标强调"轻"：一个 Python 进程 / 一个 Node 进程 / 一个数据库文件。

**旁白要点**：
> "先看答案的形状。整套系统运行起来只需要两个进程加一个数据库文件——评委的电脑上解压、两条命令就能跑。我们刻意选择了模块化单体而不是微服务：对评审而言它意味着'随时可复现'，对工程而言它意味着每一层可以独立测试。注意最底层——知识库、会话、资源包、事件流，全部在这一个文件里，这也是后面所有'可审计'能力的地基。"

**数据来源**：架构四层模型（`docs/架构设计文档.md` §1-2）；部署形态（`docs/部署说明.md`）。

## P4 · 多智能体全景：9 个角色的分工（45"）

**标题建议**：`不止 3 个智能体：9 个职责单元的分析-生成-校验-决策闭环`

**核心信息点**：
- 环形/流水线图：诊断(分析) → 切片(决策) → 检索(供料) → 生成 ⇄ 审核(校验·博弈) → 出题/判分(校验) → 掌握度(决策) → 资源组装(交付)
- 两类角色用颜色区分：**6 个调 LLM**（负责语言与语义）/ **3 组确定性纯函数**（负责策略与裁决）
- 一行点睛："**LLM 负责措辞，代码负责决策**"

**视觉布局**：横向流水线，每个节点标注角色名与一句话职责；LLM 节点与纯函数节点用两种底色——这张颜色区分在后面 P8 会再次呼应。

**旁白要点**：
> "赛题要求至少 3 个职责明确的智能体，我们实现了 9 个职责单元。但比数量更重要的是分工原则，请看颜色：蓝色节点调用大模型，灰色节点是确定性代码。所有教学决策——教什么、出什么题、前进还是回头——全部由灰色节点裁决；大模型只负责把决策翻译成学生听得懂的话。这是我们工程可靠性的第一块基石。"

**数据来源**：智能体全景与分工（`docs/设计实现方案.md` §3.1；实现 `core/agents/`、`core/mastery.py`、`core/assess.py`、`core/plan.py`）。

## P5 · 上下文隔离：每个角色"只看到该看的"（45"）

**标题建议**：`五条隔离红线：协同质量的结构性保障`

**核心信息点**（挑 3 条最有张力的讲）：
- 审核裁判**读不到任何学生画像**——裁决只认"论断与证据"，不因学生是谁而放水（防幻觉论证的核心）
- 生成端只拿画像**摘要**，判分要点**永不进学生视野**（防泄题）
- 对话日志永不进生成上下文（学生的话不会污染讲义内容）

**视觉布局**：权限矩阵简化版——角色 × 可见信息，用 ✅/🚫 标注；三条红线的 🚫 用红色放大。

**旁白要点**：
> "多智能体协同的质量上限，取决于每个角色'看到什么'。我们给每个智能体定义了严格的读写权限，其中三条是红线。最重要的一条：审核裁判的上下文里没有任何学生画像——它只裁决'这句话有没有证据'，不知道也不关心学生是谁。这保证了质量底线不会被个性化诉求稀释。"

**数据来源**：隔离矩阵（`docs/设计实现方案.md` §3.4；PRD §4 红线；实现 `core/teach_loop.py` 上下文组装）。

## P6 · 审核回路：幻觉防控的博弈机制（45"）

**标题建议**：`生成与审核的博弈：每条论断都要过堂`

**核心信息点**：
- 教学子图：检索 → 生成 → 审核 →（条件边打回）→ 重写 → 复审
- 三个机制标签：**论断级证据链**（每句话挂知识条目引用）· **NLI 三分类裁决**（支持/部分支持/未支持）· **定向打回**（只重写被驳回的那一条，不整稿重来）
- 角标：轮次硬上限防无限辩论 · 讲义只收"支持"论断

**视觉布局**：中央是带回边的子图（可直接截裁判面图），三个机制标签环绕。

**旁白要点**：
> "现在回答开场的问题：幻觉怎么防。生成的每条论断都必须挂证据引用——它引用了知识库里的哪几条；审核对每条论断独立过堂，三分类裁决；发现一句没证据，就打回**只重写那一句**——论断相互独立，整稿重写既浪费又会被翻判。超过轮次上限仍有问题的内容，出口处直接被过滤，学生永远看不到。"

**数据来源**：回路机制（`docs/设计实现方案.md` §3.2/§4.1；实现 `core/graph.py` 条件边、`core/agents/review.py` 裁决日志）。

## P7 · 实证：事件流里的天然对照组（45"）⭐ 可切实操

**标题建议**：`8.86% → 0.44%：这组数字怎么来的`

**核心信息点**：
- 对照设计的巧妙处：系统每次打回都留下两本账——**首轮裁决**（假如没有回路，交付的就是它）vs **最终裁决**（实际交付）
- 强调：无需关闭系统重跑、无主观评估——事件流里的原始记录直接聚合
- 回扣 P2："237 次打回，挽救 343 条幻觉论断，相对降幅 95%"

**视觉布局**：上半页"两本账"示意（同一教学主题的首轮/最终裁决对照）；下半页回扣 P2 的数字轴。

**实操演示位（可选，60" 内）**：切到裁判面**回放模式**，选一个有打回的会话（如评测会话），播放到 `review_done` 出现未支持论断 → 定向重写 → 复审通过的片段。**讲的时候指着回边说："这条回边每出现一次，就是回路在工作。"**

**旁白要点**：
> "这个对照最硬的地方在于：它不是事后估计。系统每打回一次，事件流里就多一条首轮裁决记录——那就是'没有审核机制的平行世界'的交付物。我们把 50 组会话的 4074 条论断全部重算：没有回路是 8.86%，实际交付 0.44%。机制的价值，用系统自己的账本证明。"

**数据来源**：`evals/ablation.py`（口径说明在文件头部）；结果 `evals/results/ablation.json`（sessions=50, rewrite_rounds=237, saved=343）。

## P8 · 教学状态机：确定性决策的因材施教（1'00"）

**标题建议**：`掌握度驱动：教什么、考什么、进退停，全部有据可依`

**核心信息点**（四象限或时间线）：
- **题型阶梯**：掌握度低出选择题（识别）、高出回答题（回忆），**只进不退**
- **脚手架**：答错后出"镜像你错误理解"的过渡题——让学生对比发现自己的问题
- **降维与进阶**：连错 2 次回前置主题补课；掌握度 ≥0.85 附加进阶挑战（赛题要求的双向迭代）
- 底色呼应 P4：这些全部是灰色节点（纯函数）的裁决

**视觉布局**：中央一条掌握度上升曲线，沿途挂四个机制标签；角落小字：置信度封顶（答对 1 次绝不宣告掌握）· 门槛 0.7 · 轮次上限防死循环。

**旁白要点**：
> "另一块基石：个性化怎么做到'可控'。系统中枢是一个 0 到 1 的掌握度数值，它驱动一切——题型由它选、进退由它定。注意两个防放水设计：只答对一次，掌握度被硬性封顶，绝不'碰巧通关'；连续答错两次，自动回到前置主题降维重教。同时它还驱动赛题要求的两个动态机制——降维解释和进阶挑战，一个兜底、一个拔高，双向都有。"

**数据来源**：掌握度数学（`core/mastery.py`——权重/封顶/门槛/连错阈值全部集中定义）；状态机（`docs/设计实现方案.md` §4.3/§4.6；实现 `core/teach_loop.py`）。

## P9 · 资源沉淀：从教学系统到生产引擎（30"）

**标题建议**：`会话结束不是终点：资源回流知识库`

**核心信息点**（一条链讲完）：
- 教学每轮的合格内容**实时沉淀**为三形态资源包：讲义 / 分阶题 / 实操指南（+ 进阶挑战）
- 会话结束可**条目化导出**：资源提炼为与知识库完全同构的条目——错题经误区提炼智能体转化为知识
- 闭环一句："导出的条目能被系统原样再次入库——**系统生产的资源，喂回了系统**"

**视觉布局**：单页流程图：教学轮 → 资源包三形态 → 条目化导出 → 回流入库，最后一步用环形箭头指回知识库图标。

**旁白要点**：
> "最后一步把'教学系统'升维成'生产引擎'：教学过程本身就是一条资源生产线，每轮合格内容实时沉淀。更关键的是出口——资源包能提炼成和知识库一模一样的条目，重新入库被下一个学习者使用。生产、沉淀、回流，这是'资源生产引擎'这个定位的硬证明。"

**数据来源**：`docs/设计实现方案.md` §4.7（实现 `core/deliver.py`、`core/export_pipeline.py`、`core/agents/distill.py`）。

## P10 · 评测证据：50 组批跑的全部数字（1'00"）

**标题建议**：`50 组差异化画像全量批跑：三项指标全部达标`

**核心信息点**（一张大表 + 一行测试基线）：

| 指标 | 赛题目标 | 实测 |
|---|---|---|
| 幻觉率 | <5% | **0.44%** |
| 画像-资源适配率 | ≥85% | **99.0%** |
| 知识点覆盖率 | ≥90% | **97.2%** |

- 表下两行：50 组画像 = 3 难度档 × 15 经验模板变体 + 掌握度梯度注入（可复现生成）；审核消融 8.86%→0.44%（回扣）
- 底部：工程基线——**213 个测试全部通过**，静态检查双零错误

**视觉布局**：达标表占 2/3 版面，实测列绿色加粗；画像分布用一行小徽章示意多样性；测试数放右下角信任背书位。

**旁白要点**：
> "所有论证最终落到数字。50 组差异化画像——覆盖三个难度档、15 种经验背景、注入与背景自洽的先验掌握度——全量批跑归档：三项赛题硬指标全部达标，幻觉率 0.44%，比目标好一个数量级。这些数字全部规则可复算，不依赖任何人工打分；交付包里附带全部原始结果和复算脚本。工程侧，213 个单元测试随源码交付。"

**数据来源**：`evals/results/report.json`（n_profiles=50；三指标与掌握度均值 0.7112）；画像设计 `evals/gen_profiles.py`；消融 `evals/results/ablation.json`；测试 `tests/`（`uv run pytest` 实测 213 passed）。

## P12 · 交付：评委自己能跑起来（30"）
