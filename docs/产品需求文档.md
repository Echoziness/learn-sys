## 1. 产品愿景

一个由多名 AI Agent 协作构成的**一对一导师**。对学生来说屏幕对面就是一个老师——会记住水平，知道该教什么，讲的内容有出处，讲错了内部有人审，听不懂会换方式，做错了会回头补基础。

**核心设计原则**：

| 原则 | 说明 |
|---|---|
| **策略与措辞分离** | 教学策略由确定性规则决定；LLM 只负责把策略翻译成学生能理解的语言 |
| **掌握度驱动** | `mastery` 向量是中枢——教什么、怎么教、什么节奏，全部由它驱动 |
| **可审计** | 每一步教学决策可溯源：哪个 agent、基于什么数据、输出什么裁决 |

## 2. 用户旅程

**主演示角色：小王**——本科大二，机械工程专业，学过 C 语言、会用 Excel，未接触数据库和 Python，目标转行数据分析。

```
小王打开系统，输入背景
  │
  ▼
系统分析画像 → "你已有 C 基础和 Excel 经验，需要系统学习以下五个主题"
  │
  ▼
┌─ 第一节：关系型数据库基础 ───────────────────────────────┐
│  讲一段 → 出选择题 → 小王选错 → 解释为什么错 → 再出一道   │
│  小王答对 → 掌握度更新 → 进入下一小节                      │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌─ 第二节：聚合查询 ────────────────────────────────────────┐
│  难度提升 → 出问答题 → 小王方向对但漏细节 → 给提示         │
│  mastery 上升到 0.67 → 进入下一主题                        │
└──────────────────────────────────────────────────────────┘
  │
  ▼
┌─ 第三节：遇到瓶颈 ────────────────────────────────────────┐
│  连错两题 → mastery 下降 → 系统决策"回基础，降维重新讲"   │
│  ── 裁判面展示：review 打回 → generate 修正 → 二轮通过     │
└──────────────────────────────────────────────────────────┘
  │
  ▼
结束：掌握度雷达图 + 学习路径图
```

## 3. 交互模型

### 3.1 两层循环

**外循环**（主题遍历）：plan 产出的教学大纲 → 逐个主题推进 → mastery 达标或遍历完即结束。

**内循环**（教学单元）：一个主题内 "讲一段 → 出题 → 判对错 → 决定下一步" 的周期，最多 3 轮。

```
SESSION ── diagnose + plan（一次性）
  │
  ┌─ 外循环：主题遍历 ─────────────────────────────────┐
  │   retrieve → generate → review → deliver           │
  │   ┌─ 内循环 ──────────────────────────────────┐   │
  │   │  teach → assess → feedback               │   │
  │   │    ├─ 通过 ✓ → 退出内循环                    │   │
  │   │    ├─ 半对 ~ → 留在内循环，给提示            │   │
  │   │    └─ 错了 ✗ → 换策略重新讲                 │   │
  │   └──────────────────────────────────────────┘   │
  │   PedagogicalAgent 决定下一个主题                    │
  └────────────────────────────────────────────────────┘
END
```

### 3.2 三种题型（按掌握度阶梯激活）

| 掌握度 | 题型 | 说明 |
|---|---|---|
| < 0.2 | 不给题 | 连基本概念都不认识，讲清楚再说 |
| 0.2-0.5 | 选择题 | 4 选项，错选后生成针对性解释——"为什么 B 是错的" |
| 0.5-0.7 | 问答题 | 自然语言自由回答，feedback 结构化评价（正确点/遗漏点） |
| > 0.7 | 操作题 | 写 SQL/pandas 在 SQLite 沙箱执行验证（Phase 5+） |

### 3.3 教学策略-题型映射（PedagogicalAgent 查表，不调 LLM）

| 掌握度 | 策略 | 题型 | 重试上限 |
|---|---|---|---|
| < 0.2 | 直接讲授 | — | — |
| 0.2-0.5 | 脚手架 | 选择题 | 3 |
| 0.5-0.7 | 苏格拉底式 | 问答题 | 3 |
| > 0.7 | 引导练习 | 选择+问答+操作 | 2 |

### 3.4 CLI 模拟学生

Phase 2-3 无前端时，用一个 JSON 驱动模拟学生行为：

```json
{"learner_id": "sim_test1", "topic_profile": {"BDA-SQL-001": {"correct_rate": 0.8}}}
```

根据 `correct_rate` 随机掷骰子决定答对/错。同一引擎在前端上线后换为真实学生输入即可。

## 4. Agent 职责

| Agent | 做什么 | 调 LLM？ | 确定性？ |
|---|---|---|---|
| diagnose | 画像 → gaps + level + summary | 是 | 否（输出受 entry_index 锚定） |
| plan | 盲区 × prerequisites → 拓扑排序大纲 | 否 | 是 |
| retrieve | gap → FTS+vec+RRF → 条目（按 cap 过滤） | 否 | 是 |
| **PedagogicalAgent** | mastery → 策略码 + 题型（查映射表） | 否 | 是 |
| generate | 策略码+条目+摘要 → 教学语言（挂 evidence_ids） | 是 | 否（受 evidence 约束） |
| review | 规则检查 + NLI 蕴含判断 → per-claim 裁决 | 半 | 半 |
| deliver | 通过论断 → 讲义+实操指南+溯源清单 | 否 | 是 |
| assess | 按题型出即时检验题 | 是 | 否 |
| feedback | 判对错 + EMA 更新 mastery + 决定进/停/退 | 半 | 半 |

**上下文隔离红线**（不可突破）：
- review 读不到任何画像字段（含 50 字摘要）
- generate 只读 `profile_summary`，不摸 `learner_profile` 原始模型
- 对话日志只进 feedback 的画像更新，永不进生成上下文

## 5. 当前状态与下一步

**已上线（Phase 1）**：diagnose · retrieve · generate · review（线性流，单次运行）

**下一步（Phase 2 重点）**：
- `plan`（纯算法拓扑排序）
- 条件路由：review 打回 → generate 重试 ≤3 轮 → 降级
- `deliver`（三形态资源组装）

**Phase 3**：assess · feedback · PedagogicalAgent · 双循环闭环

**Phase 4**：前端三画面（学生面 + 裁判面调度可视化 + 学情报告）
