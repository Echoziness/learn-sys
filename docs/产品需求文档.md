## 1. 产品定位

**面向职业培训的个性化学习资源生产引擎**：以多智能体协同（诊断 / 生成 / 审核 / 决策）为核心机制，以导学会话为生成过程，产出可沉淀、可溯源、分难度的学习资源包与学情报告。

| 端 | 角色 | 得到什么 |
|---|---|---|
| 学习者 | 培训学员 | 一对一导学会话（讲解有出处、听不懂会换方式、做错了回头补） |
| 培训管理者 | 院校 / 企业培训部门 | 每位学习者的资源包（讲义 / 分阶题 / 实操指南）+ 学情报告；多智能体调度的全程可视化与审计 |

**为什么是"引擎"而不是"陪聊"**：同一知识库 + 不同画像 → 不同资源包（难度、深度、措辞适配）；每主题仅 3-5 次 LLM 调用，边际成本极低；产出经审核沉淀，可复用、可审计——替代传统高耗能的实训资源开发（赛题原文的价值主张）。

**核心设计原则**（继承不变）：

| 原则 | 说明 |
|---|---|
| 策略与措辞分离 | 教学决策由确定性纯函数裁决；LLM 只负责把策略翻译成学生能理解的语言 |
| 掌握度驱动 | mastery 是中枢——教什么、出什么题型、进/停/退，全部由它驱动 |
| 可审计 | 每步决策可溯源：哪个 agent、基于什么数据、输出什么裁决；事件流全程记录 |
| fail-closed | 无证据即判错、无裁决视为不支持、无 expected 即回退——所有兜底从严 |

## 2. 用户旅程（演示主线）

**主演示角色：小王**——本科大二，机械工程专业，学过 C 语言、会用 Excel，未接触数据库和 Python，目标转行数据分析。

```
小王输入画像
  │
  ▼
诊断 Agent：锚定盲区与难度层级 ──→ 切片：5 个主题的拓扑路径
  │
  ▼
┌─ 逐主题导学会话（资源的生产过程）────────────────────────┐
│ 教学生成（每条论断挂 evidence_ids）→ 审核裁判（NLI 裁决，  │
│ 打回可见）→ 检验（选择题 → 回答题阶梯，错答有脚手架）    │
│ → 判分（规则预筛 + LLM 复核）→ 决策（进 / 重教 / 降维）  │
│        每轮产出实时沉淀为资源包                            │
└────────────────────────────────────────────────────────────┘
  │
  ▼
交付：三形态资源包（带溯源链）+ 学情报告
（盲区雷达 / 资源-难度匹配曲线 / 学习路径图）
  │
  ▼
对照演示：换画像（有 SQL 基础的计算机学生）→ 同一知识点
产出明显不同的资源包 —— "个性化"的直接证据
```

**裁判面（并行画面）**：agent 节点流转、review 打回回路、证据溯源侧栏——多智能体协同决策的实时可视化，面向培训管理者的审计视角。

## 3. 功能需求

### 3.1 画像输入与诊断

| FR | 内容 | 现状 |
|---|---|---|
| FR-1 | 画像输入：背景（教育/专业/经验/目标）+ 初始 mastery + 风格标签；Web 表单与 JSON 双入口 | ✅（Web 表单含双画像预设一键填充） |
| FR-2 | 学情诊断：LLM 单次调用，输出 gap_ids（收敛到本体条目 ID）+ difficulty_level + 50 字画像摘要 | ✅ |
| FR-3 | 课程切片：纯函数——gap 投影 + 前置链闭包 + 难度过滤 + 拓扑排序 | ✅ |

### 3.2 导学会话（资源的生产过程）

| FR | 内容 | 现状 |
|---|---|---|
| FR-4 | 教学内容生成：锚定条目 + 证据链（evidence_ids 强制）+ claim_type 分层（core / extension 错因扩展） | ✅ |
| FR-5 | 审核裁判：NLI 三分类 + 分级标准（core 逐字支持 / extension 概念一致）+ 打回 ≤3 轮 + 超限降级 | ✅ |
| FR-6 | 检验出题：题型阶梯（mastery <0.5 选择题 / ≥0.5 回答题，单向推进）+ 深度契约（不超本轮教学内容）+ expected 服务端校验 | ✅ |
| FR-7 | 作答判分：规则预筛（覆盖率 <0.6 判错）→ LLM 复核（概念级）→ 题意核对硬收口（missed_requirements 非空即降级）；fail-closed 全链 | ✅ |
| FR-8 | 教学决策：advance / retry / regress 纯函数；连错 2 次降维、轮次上限 5 防死循环 | ✅ |
| FR-9 | 脚手架：answer 失败后镜像错误理解的过渡选择题，答对回 answer 不计掌握度 | ✅ |
| FR-10 | 进阶挑战：主题 mastery ≥0.85 时在资源包附加进阶挑战任务（更高难度条目的引导任务，标记层实现） | ✅ |

### 3.3 资源沉淀（赛题主交付物）

| FR | 内容 | 现状 |
|---|---|---|
| FR-11 | 资源包持久化：按 (learner, entry) 归档三形态资源 + 溯源链 + 创建时间 | ✅ |
| FR-12 | 定制化讲义：通过审核的论断按轮次组装，带 evidence 溯源 | ✅ |

| FR-15 | 会话持久化：mastery 历史、决策日志、事件流落库——跨会话延续与审计的数据地基 | ✅ |

|---|---|---|

### 3.6 明确不做（范围外）

- SQL 在线执行沙箱（操作题，Phase 5+）
- generate-review 真多轮辩论（现回路 + 打回数据已充分论证"博弈与协同"）
- CLI 进一步打磨（开发自测通道，现状冻结）
- 多学习者并发管理、长期记忆推荐
- 第二领域切片（AI 应用集成）——W3 弹性项，泛化优先用"换 seeds 目录即换领域"的架构论证

## 4. 多智能体协同

| Agent | 职责 | LLM | 确定性 |
|---|---|---|---|
| diagnose | 画像 → gap_ids + level + summary（输出受本体目录锚定） | 是 | 否 |
| retrieve | 锚定 + FTS5/vec/RRF 混合检索 + 难度闸门 | 否 | 是 |
| generate | 条目 + 摘要 + 策略 → 论断（挂 evidence_ids，claim_type 分层；procedure 条目含步骤指南） | 是 | 否（受证据约束） |
| review | NLI 逐条裁决 + 打回建议（分级标准） | 是 | 半（规则兜底） |
| question | 回答题题干 + expected 同源生成（场景化、深度契约） | 是 | 否（服务端校验兜底） |
| feedback | LLM 复核 + 教学评估 + missed_requirements 检查单 | 是 | 半（fail-closed 兜底） |
| assess / mastery / plan | 出题选择、掌握度数学、切片——纯函数 | 否 | 是 |
| **deliver**（W1 已上线） | 资源包组装归档（讲义/题目/指南/进阶标记）——确定性装配，无 LLM | 否 | 是 |

**上下文隔离红线**（不可突破）：
- review 读不到任何画像字段（含 profile_summary）——审核独立性是防幻觉论证的核心；
- generate 只读 profile_summary，禁止 learner_profile 原始模型；
- 对话日志永不进生成上下文，只进画像更新与事件流；
- expected 判分要点永不进学生视野；
- 交流结果只约束教学执行层，永不反向修改课程本体与切片。

## 5. 评测指标口径（SSOT：`evals/metrics.py`）

| 指标 | 目标 | 口径 | 判定方式 |
|---|---|---|---|
| 幻觉率 | <5% | 最终裁决 unsupported 的论断数 / 总论断数（无裁决视为 unsupported，fail-closed） | 规则（review 结果聚合） |
| 画像-资源适配率 | ≥85% | 资源包难度层级与诊断难度层级的匹配率（beginner → 资源仅来自难度 ≤2 条目，依此类推） | 规则 |
| 知识点覆盖率 | ≥90% | 目标条目 keywords 在该条目资源包讲义文本中的覆盖比例（逐条目聚合） | 规则 |

三项均可批量复算、不依赖人工打分——评测脚本一遍跑出全部数字，直接写入作品文档。

## 6. 赛题要求追溯矩阵

| 赛题要求 | 出处 | 对应 FR / 证据物 |
|---|---|---|
| ≥3 个职责分工明确的智能体，"分析-生成-校验-决策"闭环 | 答题要求(2) | FR-2/4/5/8 + 裁判面可视化（FR-17） |
| 整合先验画像 + 领域知识库 | 答题要求(2) | FR-1/2/3 + SQLite 全家桶知识库 |
| ≥3 种形态个性化资源 | 答题要求(2) | FR-12 讲义 / FR-13 分阶题 / FR-14 实操指南 |
| 可视化学情与资源匹配度报告（盲区定位 / 难度匹配曲线 / 路径规划图） | 答题要求(3)① | FR-16 三图一一对应 |
| 动态迭代：降维解释 / 进阶挑战 | 答题要求(3)② | FR-8 regress + FR-10 进阶（双向） |
| 辩论与交叉验证消除幻觉、高保真溯源 | 答题要求(4)① | FR-4/5 分层审核 + evidence 溯源链 + 幻觉率 <5% 数字 |
| 动态追问与启发式交互导学 | 答题要求(4)② | FR-6 题型阶梯 + FR-9 脚手架 + 流式教学 |
| 差异化学习者适配 | 答题要求(1) | 双画像对照演示 + 适配率 ≥85% 数字 |
| 数据合规 | 答题要求(5) | 画像数据本地 SQLite 存储、无第三方上报；演示数据为虚构 |
| 完整闭环可部署 | 评分-完整性 30 | docker compose + 部署说明（FR-22） |
| 测试用例 ≥50 组、≥3 组画像、≥2 组完整示例 | 评分-实用价值 30 | FR-20 + 2 组录制会话（FR-22） |
| 视频展示画像输入→协同调度可视化→资源生成闭环 | 提交形式(1) | 双画像 → 裁判面 → 三形态资源 → 报告（分镜见路线图） |
