## 1. 产品愿景与定位

### 1.1 一句话描述

一个由多名 AI 专业教师协作组成的**一对一导师**，面向数字技术工程师培育项目（大数据分析方向），根据学习者的知识起点和能力水平，动态生成带专业出处的教学内容，并通过"讲→测→判→调"的实时交互完成教学闭环。

### 1.2 核心设计原则

| 原则 | 说明 |
|---|---|
| **教学有效性优先** | 所有功能从"一个老师要做的事情"推导，不做教学之外的事 |
| **策略与措辞分离** | 教学策略由确定性规则决定；LLM 只负责把策略翻译成学生能理解的语言 |
| **掌握度驱动** | `mastery` 向量是系统的中枢神经——教什么、怎么教、什么节奏，全部由它驱动 |
| **可审计** | 每一步教学决策都有溯源：哪个 agent 做了什么、基于什么数据、输出什么裁决 |
| **兜底不靠信任 LLM** | 生成内容被引用条目约束、审核裁决被规则 + NLI 双重验证、检索难度被闸门过滤 |

### 1.3 不做清单

- 用户系统（单学习者演示，无注册/登录/权限）
- 实时语音/视频/Canvas 交互
- 移动端适配
- 模型微调（全 prompt + 检索约束）
- 多领域同时在线（泛化演示靠换 seeds 目录重建库）
- Electron 桌面打包

### 1.4 术语

| 术语 | 定义 |
|---|---|
| **会话 (Session)** | 一次完整的 `diagnose → plan → 若干教学主题 → 结束` 的运行实例 |
| **教学主题 (Topic)** | 一条 gap（诊断出的知识盲区），对应知识库中一个或一组条目 |
| **教学单元 (Teaching Unit)** | 一次完整的 "讲一小段 → 出一个检验题 → 判对错 → 决定下一步" 的最小交互周期 |
| **教学策略 (Strategy)** | 讲授方式：直接讲授 / 脚手架 / 苏格拉底式 / 引导练习 / 挑战 |
| **题型 (Question Type)** | 检验方式：选择题 / 问答题 / 操作题 |
| **掌握度 (Mastery)** | 学习者在每个知识点上的 0.0-1.0 得分，由 EMA(α=0.3) 持续更新 |

### 3.2 从分镜倒推的功能边界

**必须上线（Phase 2-4）**：diagnose(锚定) · plan(拓扑) · retrieve(cap+RRF) · generate(策略渲染) · review(规则+NLI) · assess(choice+open 题型) · feedback(EMA+三态决策) · PedagogicalAgent(查表) · deliver(讲义+溯源清单) · 前端三画面

## 4. 交互模型

### 4.1 两层循环

```
SESSION START
  │
  ├─ diagnose（一次性）：画像 → gaps + level + summary
  ├─ plan（一次性）：gaps × prerequisites → 拓扑排序 outline
  │
  ┌── 外循环：主题遍历 ─────────────────────────────────────┐
  │                                                            │
  │   retrieve：当前 topic → 匹配条目（按 level cap 过滤）     │
  │   │                                                        │
  │   ┌── 内循环：教学单元 ────────────────────────────┐     │
  │   │                                                   │     │
  │   │   teach（generate→review）：讲一段 + 核实        │     │
  │   │       · review 打回 → generate 重写（辩论回路）  │     │
  │   │                                                   │     │
  │   │   PedagogicalAgent 查表：根据 latest mastery     │     │
  │   │       决定该出什么题（或不出题）                 │     │
  │   │                                                   │     │
  │   │   check（assess→feedback）：                       │     │
  │   │       出题 → 学生答 → 判对错 → 更新 mastery     │     │
  │   │       三态决策：                                  │     │
  │   │         ✓ 通过 → 退出内循环，进下一个 topic       │     │
  │   │         ~ 半对 → 留在内循环，给针对性提示        │     │
  │   │         ✗ 错了 → 留在内循环，换策略重新讲        │     │
  │   │         attempt_count > 3 → 强制 exit             │     │
  │   │                                                   │     │
  │   └──────────────────────────────────────────────────┘     │
  │                                                            │
  │   PedagogicalAgent 查表：决定下一个 topic 的难度方向       │
  │     mastery 上升 → advance（同 topic 更深条目）            │
  │     mastery 停滞 → retreat（回到前置 topic）              │
  │     topic list exhausted → END                            │
  │                                                            │
  └────────────────────────────────────────────────────────────┘
END
```

### 4.2 教学单元最小粒度

一个教学单元不可再分——它是一次完整的心智交互：

```
T0: master 讲一段（50-100 字，自然语言，单概念）
T1: master 出一道即时检验题
T2: student 作答
T3: master 判对错 + 给反馈 + 更新 mastery
T4: master 决定下一步（进 / 停 / 退）
```

### 4.3 三种题型

| 题型 | 适用掌握度 | 交互方式 | 判题逻辑 |
|---|---|---|---|
| **选择题** | 0.2-0.5 | 4 个选项（1 正确 + 3 典型错误），错选后生成针对性解释 | feedback 做简单匹配：选 A~D → 查 answer key → 正确/错误。distractor analysis 由 generate 预生成，错选时直接展示对应的解释 |
| **问答题** | 0.5-0.7 | 学生用自然语言自由回答 | feedback 调 LLM 做结构化评价：`{verdict, correct_points, missing_or_wrong, follow_up}` |
| **操作题** | > 0.7 | 学生写 SQL/pandas 代码，在本地 SQLite 沙箱执行并验证结果 | assess 生成题目模板 + 预期结果 SQL；feedback 执行沙箱 → 比较结果集 → 判定 + 生成差异说明 |

### 4.4 教学策略-题型映射表（PedagogicalAgent 查表逻辑）

| 掌握度 | 策略 | 题型 | 通过条件 | 重试上限 |
|---|---|---|---|---|
| < 0.2 | 直接讲授 | 不给题 | N/A | N/A |
| 0.2-0.5 | 脚手架 | 选择题 | 答对 1 题 | 3 次 |
| 0.5-0.7 | 苏格拉底式 | 问答题 | verdict=correct 或 2 次 partial 后 advance | 3 次 |
| > 0.7 | 引导练习 | 选择题 + 问答题 + 操作题 | 全部答对 | 2 次 |
| > 0.9 | 挑战 | 操作题 | 1 次正确 | 1 次 |

### 4.5 CLI 模拟阶段的模拟学生

Phase 2-3 无前端，用一个 JSON 配置文件驱动模拟学生行为：

```json
{
  "learner_id": "sim_test1",
  "topic_profile": {
    "BDA-SQL-001": { "correct_rate": 0.8 },
    "BDA-SQL-004": { "correct_rate": 0.3 },
    "BDA-ST-001": { "correct_rate": 0.6 }
  },
  "choice_strategy": "random_weighted",
  "open_answer_style": "brief_and_mostly_correct"
}
```

feedback 根据 `correct_rate` 随机掷骰子决定该题答对还是答错，并模拟一段自然语言回答（模板生成）。同一个引擎在 Phase 4 前端上线后，将 `student_answer` 的来源从模拟器切换到前端 SSE 消息即可。

## 5. Agent 体系设计

### 5.1 教学行为 → Agent 职责映射

| 一个老师做的事 | 谁做 | 调用 LLM？ | 确定性 |
|---|---|---|---|
| 了解学生的背景和知识起点 | diagnose | 是 | 否（输出受 entry_index 锚定约束） |
| 规划这节课教什么、按什么顺序 | plan（纯算法） | 否 | 是 |
| 从教材里找到适合这个学生的内容 | retrieve | 否 | 是 |
| 决定用什么方法教、出什么类型的题 | **PedagogicalAgent（新增）** | 否 | 是（查表） |
| 把教材内容翻译成学生能懂的话 | generate | 是 | 否（受 evidence_ids 约束） |
| 核实讲的内容有没有偏离教材原文 | review | 半 | 半（规则层确定，NLI 层用 LLM） |
| 把教学内容组织成讲义+溯源清单 | deliver | 否 | 是 |
| 出即时检验题 | assess | 是 | 否（schema 约束题型+答案） |
| 判题 + 给反馈 + 记录学生掌握了多少 | feedback | 半 | 半（规则判题确定，LLM 生成反馈文本） |

## 6. 功能需求

> 每条 FR 的验收标准 = 对应分镜时间段内这段能被录成视频。

### FR-01 学情诊断（diagnose）

**描述**：输入学习者背景 + 前置测试 + 条目目录 → 输出锚定到条目 ID 的 gap 清单、画像摘要、水平评估。

**分镜覆盖**：#3（1:00-1:30）

**验收标准**：
- 输出 3-5 个 gap，每个 gap 对应 ≥1 个知识库条目 ID（W3 接入 entry_index 后）
- `profile_summary` ≤ 50 字，仅包含与教学难度和举例风格相关的信息
- `difficulty_level` 随 mastery 变化而变化（第二次会话读到更新后的 mastery 后 level 从 beginer 升为 intermediate）

### FR-02 路径规划（plan）

**描述**：纯算法——读 gap 对应的条目 ID，查 `prerequisites` 字段，拓扑排序为大纲。

**分镜覆盖**：#3-#4（plan 产出的 outline 驱动后续主题遍历顺序）

**验收标准**：
- outline 中前置条目排序不晚于其依赖的条目
- 环检测：有环的 prerequisites 记录日志 + 按原始 gap 顺序兜底
- 纯函数，pytest 覆盖

### FR-03 混合检索（retrieve）

**描述**：按 gap 对应条目 ID 精确取原文（W3 起）；同时对自由文本 gap 做 FTS+vec 双路 RRF 融合，按 difficulty cap 过滤。

**分镜覆盖**：#4（1:30-3:00）

**验收标准**：
- FTS 任意合法输入不崩溃（回归测试）
- 中文子串可命中（CJK 逐字切分）
- 向量维度随 encoder 自适应
- 初学者 cap=2 时不返回难度 ≥3 的条目（回归测试）
- 覆盖度低于阈值 → `uncovered_gaps` 标记，generate 显式标注 "知识库未覆盖"

### FR-04 内容生成（generate）

**描述**：接收教学策略码 + 检索条目 + 画像摘要 → 生成一段 50-100 字的自然语言教学段落。每条论断挂 `evidence_ids`（min_length=1，schema 层强制）。

**分镜覆盖**：#4（1:30-3:00）、#6（4:30-5:30 追问）、#7（5:30-6:30 辩论修改）

**验收标准**：
- 证据缺失 → `chat_validated` 触发修复重试
- 教学策略码正确展开为对应的教学风格文本
- 辩论回路中能根据 `last_review_feedback` 逐条修改论断
- 追问模式下用 cited_entries 回答，不新开检索

### FR-05 审核裁判（review）

**描述**：两层——规则层（evidence_ids 是否存在 → 直接 unsupported）+ NLI 层（引用原文是否支持论断）。每条论断恰好一条裁决，漏判 fail-closed。

**分镜覆盖**：#7（5:30-6:30，核心桥段）

**验收标准**：
- 规则层 + NLI 层不双重计数
- NLI 漏判 → fail-closed 记 unsupported
- `claim_index` 越界 → drop + warning
- **零画像字段泄漏**（code review 确认 `review_node` 全文无 `learner_profile` 引用）

### FR-06 辩论回路

**描述**：条件路由——review 全 supported → deliver；存在打回 + 轮次 <3 → generate（携 structured feedback）；轮次耗尽 → 降级 deliver（移除 unsupported 论断 + 显式标注）。

**分镜覆盖**：#7（5:30-6:30）

**验收标准**：
- `review_history` append 链含全部轮次（pytest 验证）
- 超限必走降级路径
- 降级时 `final_resources` 含移除声明

### FR-07 三形态交付（deliver）

**描述**：通过论断重组为三形态——讲义、实操指南、溯源清单（论断 → evidence_ids → 条目标题 → source 四级链路）。

**分镜覆盖**：#4（1:30-3:00）、#5（3:00-4:30 评测）、#7（辩论后交付）

**验收标准**：
- 三种形态结构互异（非同文换皮）
- 溯源清单覆盖率 100%

### FR-08 即时检验（assess）

**描述**：按 PedagogicalAgent 指定的题型出题——选择题（4 选项 + distractor analysis 预生成）或问答题（开放题）。题目走复习核链（与 FR-05 相同）。

**分镜覆盖**：#5（3:00-4:30）

**验收标准**：
- choice 题型：4 选项，3 个错误选项的解释源自条目原文
- open 题型：开放问，学生自由回答
- 题目 schema 含 answer key + distractor_analysis

### FR-09 掌握度反馈与决策（feedback + PedagogicalAgent）

**描述**：
- **feedback**：判题 → 结构化评价 → EMA(α=0.3) 更新 mastery → 三分裁决（correct/partial/incorrect）
- **PedagogicalAgent**：纯查表——mastery → 策略 + 题型 → 路由决策（advance/retreat/stay）

**分镜覆盖**：#5（3:00-4:30 更新）、#8（6:30-8:00 降维）、#9（8:00-9:00 mastery 雷达图）

**验收标准**：
- feedback 二分评价含 `correct_points` + `missing_or_wrong` 字段
- mastery 更新后写 DB（`learner_profiles` + `profile_updates` 流水）
- 同一学习者两次运行后 mastery 向量有可解释变化
- PedagogicalAgent 三态决策均可触发并有日志

### FR-10 调度可视化（裁判面）

**描述**：React Flow 渲染 8+ 节点有向图；SSE 实时状态颜色机（灰=排队 / 蓝脉冲=执行中 / 绿=通过 / 红=打回）；辩论轮次 badge；节点点击查看 I/O 快照。

**分镜覆盖**：#9（8:00-9:00）

### FR-11 学情报告（裁判面）

**描述**：Recharts 掌握度雷达图（多轮次对比）+ React Flow 学习路径图（outline 拓扑可视化 + completed/current/pending 三色标记）。

**分镜覆盖**：#10（9:00-9:30）

### FR-12 资源展示（学生面）

**描述**：三形态资源 Tab 渲染；每条论断溯源标注可点击展开条目原文 + 出处；未覆盖盲区明示样式。

**分镜覆盖**：#4-#8（贯穿学生面所有交互）

### FR-13 知识库领域化与幂等加载

**描述**：知识条目为 `data/seeds/<domain>/entries.jsonl` 一等数据文件；loader 幂等入库；FTS 表 + vec 表每次重建。

**验收标准**：同一 seeds 目录连续 `init_db.py` 两次 → 计数不变、不崩 UNIQUE。第二领域 seeds 目录跑通同一 CLI 全流程。

### FR-14 会话持久化与回放

**描述**：每次 session 写 `run_history` → `generated_resources` → `conversation_logs`。任意 run_id 可回放完整中间数据。

**验收标准**：回放模式在无 LLM key 环境下可完整演示全部 agent 状态变迁。

## 7. 数据需求

### 7.1 知识库（DR-01）

| 维度 | 要求 |
|---|---|
| 主演示库（bigdata-analysis） | ≥120 条，覆盖大数据分析职业标准核心模块 |
| 泛化切片库（ai-engineering） | 30-50 条，演示换领域 |
| 条目必含字段 | id / title / content / prerequisites / difficulty / keywords / source |
| 生产 SOP | AI 草稿 → schema 自动校验 → 抽审 ≥10% |
| 入库 | `init_db.py` 幂等写入；FTS 表经 CJK 逐字切分；vec 表维度随 encoder 自适应 |

### 7.2 学习者画像（DR-02）

| 用途 | 数量 | 特征要求 |
|---|---|---|
| 评审用画像 | ≥3 组 | 画像特征显著差异化（零基础 / 有编程基础 / 在职提升） |
| 评测用画像 | 50 组 | 画像生成器按维度组合（学历×专业×经验×目标）+ 种子扰动 |
| 每组含 | — | 输入画像 + 协同决策中间数据（FR-14 快照）+ 最终三形态资源 |

### 7.3 合规（DR-03）

全部数据为合成数据，不含真实个人信息。材料文档附脱敏与合规声明。

## 9. 评测体系

指标口径的唯一实现为 `evals/metrics.py`，CLI / API / 前端 / 评测脚本共用同一段代码。

| 指标 | 目标 | 定义 |
|---|---|---|
| 幻觉率 | <5% | 最终裁决 unsupported 论断数 / 总论断数（fail-closed） |
| 画像-资源适配准确率 | ≥85% | 资源 difficulty 落在画像 ZPD 区间（mastery ± 0.2 映射 difficulty 1-5）的比例 |
| 知识点覆盖率 | ≥90% | 产出素材覆盖条目 ID 数 / 诊断 gap 锚定的条目集合 |
| 测试用例 | ≥50 组 | `evals/run.py` 批量执行，谷时运行 |

## 11. 风险与假设

| # | 风险/假设 | 缓解措施 |
|---|---|---|
| R1 | `entry_index` 接入后 diagnose 锚定 quality 有波动 | 锚定基于精确 ID 匹配而非语义——质量由目录完整度控制 |
| R2 | 模拟学生无法真实还原交互节奏 | 模拟器的每个 topic 配置了 `correct_rate`，覆盖高/中/低三种情形 |
| R3 | 前端延期 | P4 最重头画面是裁判面调度可视化——优先此页；学生面可用 CLI 替代演示 |
| R4 | Open 题型 LLM 判对错不稳定 | feedback 使用结构化输出 schema + chat_validated 校验，错误重试一次 |
| A1 | 评委评审时有可用的 LLM API key | 回放模式兜底——无 key 也可完整演示 |
| A2 | 班级教学节奏——一个 session 约 3-5 个教学主题是合理的演示规模 | 每个 topic 预计 2-3 个 unit，10 分钟视频约展示 3 个 topic |
