# 需求规格说明书

> 版本：v1.0 · 2026-07-21
> 地位：本项目功能与验收的单一事实源。赛题原文条款 → 需求 ID → 验收标准全链可追溯。
> 变更纪律：任何需求增删必须先改本文档并注明原因，再动代码。

---

## 1. 范围

### 1.1 产品定位

面向"数字技术工程师培育项目"（大数据分析方向·初级）的个性化培训引擎：以多智能体协同决策实现"学情诊断 → 路径规划 → 知识检索 → 内容生成 → 审核辩论 → 三形态交付 → 测评反馈 → 动态决策"的完整闭环，并通过更换知识库种子目录泛化到其他职业标准领域。

### 1.2 评分结构驱动（一切优先级的锚）

| 评分项 | 分值 | 对应需求区 |
|---|---|---|
| 作品完整性 | 30 | FR-01 ~ FR-09（全流程闭环） |
| 技术创新性 | 25 | FR-05、FR-06、FR-07、NFR 防幻觉体系 |
| 用户体验 | 15 | FR-10、FR-11、FR-12 |
| 实用价值 | 30 | DR 全部、NFR-01、评测指标（§6） |

### 1.3 不做清单（Out of Scope，克制原则）

- 不做用户系统（单学习者演示，无注册/登录/权限）；
- 不做实时语音/视频交互；
- 不做移动端适配（演示环境为桌面浏览器）；
- 不做模型微调（全部走 prompt + 检索约束）；
- 不做多领域同时在线（泛化演示 = 换 seeds 目录重建库，非运行时切换）；
- Electron 桌面打包（缓冲周可选加分，非承诺项）。

## 3. Agent 名册与上下文隔离总表

防幻觉机制的代码级基础。每个节点只读表内字段，写表内字段；越界访问即 code review 驳回项。

| 节点 | 类型 | 可读 state key | 可写 state key | 职责一句话 |
|---|---|---|---|---|
| diagnose | LLM | `learner_profile`, `test_results`, `entry_index` | `gaps`, `profile_summary` | 画像+测试 → 盲区锚定到条目 ID |
| plan | 纯算法 | `gaps`（+DB 查 prerequisites） | `outline` | 盲区按前置依赖拓扑排序为教学大纲 |
| retrieve | 基础设施 | `gaps`, `outline` | `retrieved_entries`, `uncovered_gaps` | FTS5+vec 混合检索，判定覆盖度 |
| generate | LLM | `retrieved_entries`, `profile_summary`, `outline`, `last_review_feedback`, `uncovered_gaps` | `draft`, `cited_entries` | 基于条目原文生成带引用的教学内容 |
| review | LLM+规则 | `draft`, `cited_entries`, `review_round` | `review_history`(append), `review_round`, `last_review_feedback` | NLI 逐条裁决，**禁止任何画像字段** |
| deliver | 模板组装 | `draft`, `review_history`, `retrieved_entries` | `final_resources` | 通过论断重组为讲义+实操指南+溯源清单 |
| assess | LLM | `final_resources`, `cited_entries` | `quiz`, `quiz_review` | 生成分阶测试题，同走审核链 |
| feedback | LLM+规则 | `quiz`, `quiz_answers`, `learner_profile.mastery` | `learner_profile.mastery`, `feedback_decision` | EMA 更新掌握度，决策降维/进阶/下一主题 |

隔离红线（评审核心论点，不得突破）：
1. review 读不到任何画像字段（含 `profile_summary`）；
2. generate 读不到 `learner_profile` 原始模型，只读 50 字 `profile_summary`；
3. 对话日志只进 feedback 的画像更新，永不进任何生成上下文。

## 4. 功能需求

### FR-01 学情诊断（diagnose）— 已上线，W3 增强

- 输入：学习者背景（学历/专业/经验/目标）+ 前置测试结果（可空）+ 条目目录 `entry_index`（id+title，W3 接入）
- 输出：`gaps`（≤5 个盲区，锚定条目 ID）、`profile_summary`（≤50 字）
- 验收：盲区全部落在知识库条目空间内（W3 起）；不同画像产出不同盲区组合
- 赛题映射：(1)(2)；评分-完整性

### FR-02 路径规划（plan）— W2 新增

- 输入：`gaps`；条目前置依赖（DB `knowledge_entries.prerequisites`）
- 输出：`outline`（拓扑排序的教学大纲：前置未掌握的条目插队在先）
- 验收：大纲中任意条目的前置条目排名不晚于它本身；纯函数可单测（不调 LLM）
- 赛题映射：(3)① 学习路径规划图的数据源

### FR-03 混合检索（retrieve）— 已上线

- 输入：`gaps`（W2 起兼读 `outline` 顺序）
- 输出：`retrieved_entries`（RRF 融合去重）、`uncovered_gaps`（覆盖度不足判定）
- 验收：FTS 任意输入不崩溃（回归测试）；中文子串可命中；未覆盖判定有日志
- 赛题映射：(2) 领域知识库整合

### FR-04 内容生成（generate）— 已上线

- 输入：检索条目+画像摘要+大纲+上轮审核反馈+未覆盖清单
- 输出：`draft`（3-5 条论断，每条 `evidence_ids` 非空，schema 强制）、`cited_entries`
- 验收：无证据论断在 schema 层即拒绝并触发修复重试；未覆盖盲区显式标注「知识库未覆盖」而非编造
- 赛题映射：(2)(4)①；评分-创新性（生产约束层）

### FR-05 审核裁判（review）— 已上线

- 输入：`draft`、`cited_entries`（规则层查引用有效性；NLI 层判蕴含）
- 输出：每条论断恰好一条裁决（supported/partially_supported/unsupported）+ 修改建议
- 验收：规则层与 NLI 层不双重计数；NLI 漏判 fail-closed；上下文零画像（隔离红线 1）
- 赛题映射：(2)(4)①；评分-创新性（信息隔离层）

### FR-06 辩论回路（条件路由）— W2 新增

- 逻辑：review 后路由——全 supported → deliver；存在打回且轮次 <3 → generate（携 `last_review_feedback` 逐条回应：采纳/反驳+理由）；轮次耗尽 → 降级 deliver（仅 supported 论断重组，并标注「以下论断经 3 轮辩论未通过审核已移除」）
- 验收：打回场景重生成后 `review_history` 含全部轮次（append 链）；超限必走降级；辩论链在 CLI/前端可完整回放
- 赛题映射：(4)① 核心创新叙事；评分-创新性

### FR-07 三形态交付（deliver）— W2-W3 新增

- 输入：通过的 `draft` + `retrieved_entries`
- 输出 `final_resources` 三形态同次产出：
  1. **定制讲义**：论断重组为带难度进阶的章节文本；
  2. **实操指南**：从条目提炼步骤式操作卡（如 SQL/pandas 可当场运行的示例代码块）；
  3. **分阶测试题**：移交 assess 生成（FR-08 输入）
  另附**溯源清单**：每条论断 → evidence_ids → 条目标题 → source 出处，四级链路。
- 验收：三种形态结构各异（非同文换皮）；溯源清单覆盖率 100%
- 赛题映射：(2) ≥3 种形态硬性要求

### FR-08 测评与反馈迭代（assess + feedback）— W3-W4 新增

- assess：按 outline 难度分层出题（基础/进阶/挑战 ≥3 档），题目走与 FR-05 相同的审核链
- feedback：答题结果 → EMA 更新 `mastery[entry_id]`（EMA α=0.3，初值 0）→ 规则决策：
  - 正确率 <60% → 降维解释（同主题更浅表述重生成）
  - 60-85% → 下一主题
  - ≥85% → 进阶挑战（更高 difficulty 条目）
  更新结果写回 DB（`learner_profiles` + `profile_updates` 流水）
- 验收：同一学习者两轮后 mastery 向量有可解释变化；决策分支三态均可触发并有日志
- 赛题映射：(3)② 动态迭代机制；评分-完整性闭环最后一环

### FR-09 运行持久化 — W4 新增

- 每次图执行写 `run_history`（状态快照）+ `generated_resources`（三形态产物）+ `conversation_logs`
- 验收：任意 run_id 可回放完整中间数据（评审材料「多智能体协同决策中间数据」的数据源）
- 赛题映射：提交-测试数据

### FR-10 调度可视化页 — W5 新增

- SSE 消费图执行事件流；React Flow 渲染 8 节点编排图；状态颜色机（灰=排队/蓝脉冲=执行中/绿=通过/红=打回）；辩论轮次 badge；点击节点查看该节点输入/输出快照
- 验收：一次完整运行中前端实时反映每个节点状态变迁，无卡顿（50ms 文本缓冲）
- 赛题映射：(3)①；评分-用户体验（最重头画面）

### FR-11 学情报告页 — W5 新增

- Recharts：掌握度雷达图（mastery 向量）、资源难度匹配曲线（条目 difficulty vs mastery 的 ZPD 区间）；React Flow：学习路径规划图（FR-02 的拓扑大纲可视化）
- 验收：三件套图表同源于一组真实运行数据
- 赛题映射：(3)① 知识盲区定位/难度匹配曲线/路径规划图逐字对应

### FR-12 资源展示页 — W5 新增

- 三形态资源分 tab 渲染；每条论断的溯源标注可点击展开条目原文+出处；未覆盖盲区有「知识库未覆盖」明示样式
- 验收：排版规范；溯源点击链路完整
- 赛题映射：(3)①；评分-用户体验

### FR-13 知识库与领域泛化 — 贯穿 W2-W5

- 知识条目为一等数据文件（`data/seeds/<domain>/entries.jsonl`），loader 幂等入库
- 主演示库 bigdata-analysis：≥120 条，覆盖职业标准全部职业功能模块
- 泛化切片库 ai-engineering：30-50 条，演示「换 seeds 目录 = 换领域」
- 验收：第二领域库跑通同一 CLI 全流程（诊断→生成→审核）
- 赛题映射：(1)(6)；评分-实用价值（可迁移性）

### FR-14 启发式追问导学（可选加分）— 缓冲周，有时间才做

- 学习者对讲义某论断发起追问 → generate 携该论断的 cited_entries 作答（不新开检索）
- 验收：追问回答仍受 evidence 约束（可审核）
- 赛题映射：(4)② 加分项；**不做不影响主评分**

## 5. 数据需求（DR）

### DR-01 知识库切片（提交物）

- 主演示库 ≥120 条（W2 +20 / W3 +25 / W4 +30 / W5 +30 节奏，当前 15 条）
- 每条含 id/title/content/prerequisites/difficulty/keywords/source 七字段；content 为官方文档理解性改写（版权合规）
- 生产 SOP：AI 草稿 → 脚本自动校验（schema、前置依赖存在性、difficulty 1-5）→ 核心条目抽审 ≥10%

### DR-02 学习者画像（提交物）

- 评审用精修画像 ≥3 组：机械转行者（现有 test1）、计算机在校生、在职提升者，画像特征显著差异化
- 评测用批量画像 50 组：画像生成器按维度组合（学历×专业背景×经验×目标）+ 种子扰动
- 每组含完整输入输出示例：画像特征 + 协同决策中间数据（FR-09 快照）+ 最终三形态资源

### DR-03 合规声明

- 全部数据为合成数据，不含真实个人信息；材料文档附脱敏与合规声明段落
- 赛题映射：(5)

## 6. 指标口径（SSOT = evals/metrics.py）

| 指标 | 目标 | 口径 | 测量方式 |
|---|---|---|---|
| 幻觉率 | <5% | 最终裁决 unsupported 论断数 / 总论断数（fail-closed，无裁决计 unsupported） | 审核链自动判定 + 人工抽检 20% 信度验证 |
| 画像-资源适配准确率 | ≥85% | 资源难度落在画像 ZPD 区间（mastery±0.2 映射 difficulty 1-5）的比例 | 规则计算 + LLM-judge 双轨取保守值 |
| 知识点覆盖率 | ≥90% | 产出资源覆盖条目 ID 数 / 诊断盲区锚定条目集合 | 纯程序计算 |
| 测试用例 | ≥50 组 | 批量画像 × 生成任务全跑通 | evals/run.py 谷时执行 |

任何代码（CLI、API、前端、评测）需要上述数值时，必须调 `evals/metrics.py`，禁止就地另算。
