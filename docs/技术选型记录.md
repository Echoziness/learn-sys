## 2. 领域选型

### 2.1 决定

- **主演示库：大数据工程技术人员（初级 · 大数据分析方向）**
  国家职业技术技能标准（2021 年版），职业编码 2-02-10-11。
- **泛化演示库：人工智能工程技术人员（初级 · AI 应用产品集成实现方向）**
  同体系标准，职业编码 2-02-10-09，30-50 条切片。
- **整体叙事：面向"数字技术工程师培育项目"的个性化培训引擎。**

### 2.2 依据

| 维度 | 大数据分析（选定） | 软考软件设计师（落选） | AI 应用集成（降为切片） | 1+X Web 前端（出局） |
|---|---|---|---|---|
| 条目式友好 | 方法体系边界清晰（SQL/统计/算法） | 考纲即条目，最优 | 概念+流程混合，工程文本松散 | — |
| 内容稳定性 | 经典内容数十年不变 | 2018 大纲 8 年未改版 | 2021 标准不含大模型，写经典显旧、写新的无背书 | — |
| 权威来源 | 标准 PDF 公开 + 官方教材 + SQL/pandas 公开文档 | 备考资料海量但应试导向 | 教材无电子版 | — |
| 实操演示性 | SQL/Python 可当场运行 | 应试无实操 | 较好 | — |
| 培训生态 | 数字技术工程师培育项目（128 学时、职称贯通、政府补贴） | 几十年历史 | 同左 | 2025-12-31 体制撤销中 |

**结论**：主演示库必须同时满足条目式 + 内容稳定 + 权威背书 + 可实操，只有大数据分析四项全占。

## 3. 技术栈选型

### 3.1 定型总表

| 层 | 选型 | 关键理由 |
|---|---|---|
| 编排框架 | **LangGraph Python ≥1.0** | 见 3.2 |
| 后端 | **FastAPI + SSE** | SSE 单向推送图执行事件，比 WebSocket 实现量减半 |
| 存储 | **SQLite 全家桶**：业务表 + FTS5 全文 + sqlite-vec 向量 + RRF 融合 | 单文件 DB、零外部依赖、评委环境零额外组件 |
| Embedding | **BGE-M3 本地**（sentence-transformers） | 检索栈全离线；评委只需一个 LLM key；批量评测零成本 |
| LLM 入口 | `core/llm.py` → **AsyncOpenAI client**，base_url + api_key 注入 | 不预设模型名，不硬编码 provider |
| 前端 | **Next.js 15 + TS strict + Tailwind v4 + shadcn/ui + React Flow + Recharts** | AI 语料收敛栈 |
| 交付 | **docker compose** | 比赛交付标准形态（2026-08-27 改判：赛题无容器要求，构建网络/代理/镜像体积失败面实测踩过，改为本地部署，见 `docs/部署说明.md`） |
| 包管理 | Python → **uv** · JS → **pnpm** | — |

### 3.2 编排框架：LangGraph Python（否决 JS 版）

**证据**（2026-07 检索）：

- LangGraph 1.0 于 2025-10 GA；Klarna/LinkedIn/Uber/Replit 生产在用，token 开销为三大框架最低（+9%）
- **AutoGen 已死**：微软转入维护模式；CrewAI 无持久化只适合原型
- **JS 版 parity 差距是实坑**：GitHub issue #1767 — `createAgent` 在 JS 版无法作为 StateGraph 节点，官方 1.0 核心组合模式在 JS 侧不成立；月下载 LG.py 4.3M vs LG.js 1.8M

**结论**：本项目创新核心是自定义图逻辑（辩论回路、子图、条件路由），重度使用 parity 差距所在的高级特性。

### 3.3 模型策略

统一走 **OpenAI 兼容协议**，provider 抽象层切 base_url + api_key + model 即换模型。内部实现为 `AsyncOpenAI` client，不做二次封装厂商 SDK。环境变量注入，不预设模型名。

### 3.4 否决记录

| 方案 | 否决原因 |
|---|---|
| AutoGen | 2026 年已处维护模式，无新功能 |
| CrewAI | 无持久化层，工作流中途失败须从头重跑 |
| Chroma / LanceDB / Pinecone | 引入第二个存储组件；SQLite 全家桶可单文件承担全部检索 |
| LangGraph JS | 见 3.2 |
| Streamlit / Gradio | 调度可视化+学情报告+资源排版三画面需求超出其布局能力 |
| Chainlit | 2025-05 创始团队退出；2025 底曝两个高危漏洞 |
| FTS5 trigram 分词器 | **实测排除**：2 字中文词会静默匹配全表，比 unicode 的"单长 token 无法子串匹配"问题更危险 |
| 微服务 / 消息队列 | 单人项目最大隐性风险：过度架构 |

### 3.5 知识库内容来源

1. 标准 PDF（政府官网公开）→ 条目骨架：职业功能 / 工作内容 / 相关知识要求直接映射
2. 条目正文：SQL/pandas 官方文档 + 经典教材的理解性改写（禁直接复制，版权合规）
3. 每条标注 `source` 出处，溯源链直通官方文档

## 4. 架构决策（2026-08-14 补录）

### 4.1 产品定位：资源生产引擎 + 导学会话为生产过程

**决定**：系统定位为"面向职业培训的个性化学习资源生产引擎"，导学会话是资源的生产过程而非产品本身。每轮教学中通过审核的论断与题目实时沉淀为三形态资源包（讲义/分阶题/实操指南），按 (learner, entry) 持久化。

**依据**：赛题评分主语是"领域知识个性化生成"，价值主张原文"资源生产引擎，以极低边际成本替代传统高耗能的实训开发"。已有教学内核（审核/判分/决策）转译为"资源可信"的生产工艺，增量代码集中在装配层（deliver），不动内核。

**否决**：继续按"一对一 AI 导师"打磨教学体验——边际收益趋零，且不产生赛题要求的资源形态证据物。

### 4.2 会话事件流：一表三用（裁判面渲染 / 回放演示 / 审计日志）

**决定**：统一 `session_events` 表（seq 单调 + payload 自包含）。实时会话边执行边写库并推 SSE；回放模式按 seq 重放同一流，前端渲染代码复用。

**依据**：评委环境可能无 LLM key（风险表早有预案），回放是演示兜底；"多智能体协同决策中间数据"是赛题提交物硬要求；裁判面需要渲染协议。三者共用一个事件流，实现一次覆盖三需求。

**否决**：LangGraph astream_events 直接透传——覆盖不了 CLI 驱动的内循环（出题/作答不在图内），且 payload 不自包含，前端无法脱离 DB 渲染。

### 4.3 产出物与知识库同构（2026-08-23 拍板）

**决定**：资源包必须可复用——`package_to_entry` 把资源包提炼为与知识库 `SeedEntry` 完全同构的条目（`scripts/export_packages.py` 导出，自检后可被 init_db 原样入库）。进库的是知识本身：讲义 supported 论断直接拼接；错题/脚手架是原料，经 distill agent 提炼为误区知识段落才进库。

**依据**：赛题题目即"领域知识个性化生成"——生成的资源若不能复用，"资源生产引擎"定位不成立（实用价值分的"可迁移能力"同理）。同构规范让"沉淀与否"解耦为后续动作：格式统一了，入库就是零成本。

**否决**：错题/脚手架原文进库（它们是教学过程数据不是知识）；立即做资源回流知识库的自动闭环（13 天死线内属危险扩张，同构规范已是充分准备）。

## 5. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| AI 生成代码过度架构 | 高 | AGENTS.md 明令模块化单体、禁微服务/MQ；新依赖须先记录理由 |
| sqlite-vec AI 语料密度低 | 中 | 手写 30 行参考实现定 pattern，AI 照抄；检索层封装抽象接口可换 Chroma |
| LangGraph 高级特性坑 | 中 | W1 先技术验证；只用官方文档确认过的 API |
| 知识库进度拖期 | 高 | 种子条目 15 条先支撑链路；后续 AI 批量草稿 + 脚本自动校验 |
| 评委环境无法跑 LLM API | 中 | 预生成运行记录（事件流落库），支持"回放模式"演示（§4.2 事件流已落地） |
| 幻觉率实测超标（>5%） | 中 | W2 首日小批评测；调 generate 证据锚定与 review 严格度（路线图 W2.3） |
